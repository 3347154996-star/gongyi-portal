其他检具接入流程

先收集资料与登记，再由维护人员适配。单台在最终服务器上验证通过后，分批接入其他检具。

登记不等于接通“登记检具”保存的是待配置台账。卡片出现后，不会自动创建采集程序、读取新共享或产生检测结果；待配置设备没有虚构数据。

部署后，现有连接方式还能用吗？

厂内 Windows 部署

满足网络和权限条件，可继续读共享

检具持续生成采集结果，由最终门户服务器读取授权的只读共享。手机和浏览器通过网页查看，无需直接连接 SMB。

  • 验证最终服务器到检具的网络路径。
  • 确认实际运行门户服务的账号能读取文件。
  • 验收重启后的采集、认证和服务恢复。
公网云 / 生产网络之外

需要另做上传或 IT 专用网络

云服务器不能直接访问厂内私有地址共享。可由维护人员开发 HTTPS 主动上传，或由 IT 提供受控专用网络。

  • 上传需要设备鉴权、断线重试和去重。
  • 上传链路当前尚未实现。
  • 不要把 SMB 的 445 端口直接开放到公网。

部署形式尚未确定。本指南不预设迁移方案；原电脑能读到，不代表换服务器后也能读到。

换服务器怎么办当前能力七步接入单台验收填写信息表前提与局限

如果放到厂内服务器，需要重新配置什么？

换服务器需部署和验收服务器这一侧。共享读取方式、检具输出和共享路径都不变时，检具端采集程序通常不用改。由服务器主动读共享，服务器地址变化不要求检具向新地址发送数据；同事通过新的网页地址访问。

由维护人员与 IT 执行的迁移清单

部署地点尚未确定，以下是条件与交付要求，当前未实施这些操作。

  • 在新服务器部署门户程序、运行环境，确定实际服务账号。
  • 在维护时段停止原门户写入并备份；目标已有数据时也先停止相关服务并备份。迁移已保存的 runtime 业务数据，核对数量、登记和配置，避免空目录或默认文件覆盖已有数据。
  • 保留原检具设备编号和来源归属，现有 vision-01 继续使用。
  • 共享位置未变时可沿用同一路径，但须在新服务器、实际服务账号下重新验证网络、共享及文件权限。
  • 共享凭据不会随代码自动迁移。由 IT 在新服务器本机配置，密码由授权人员自己填写，不放进文档或聊天。
  • 配置并验证开机启动、重启后的认证和读取，确认检具原有持续采集正常。
  • 按用户访问范围配置网页监听、限定的防火墙规则及 HTTPS，从同事的电脑或手机实际访问验收。
  • 比对历史记录、设备归属、最新检测和页面状态，通过后再切换网页地址，保留可恢复备份。
如果只是让同事访问当前电脑不需要因此重配检具采集。维护人员需单独处理网页监听、访问范围、防火墙和 HTTPS，并从其他电脑验收。当前服务仅监听本机回环地址，只能确认本机可用，尚不能宣称已在局域网开放。

当前已完成什么，还需要适配什么？

已有接入

前副车架 Front11 / Front12

已适配 Tesla_Front11、Tesla_Front12 普通检测的 61 项数据及共享读取。实时情况以页面状态和最后扫描时间为准。

管理入口

线体、检具选择与待配置登记

保留现有前副车架入口；管理员可登记新设备、接入意向和资料。登记本身不启用数据连接。

新设备需单独配置

现有 v2 包不能直接复制给多台

现有免安装包固定使用 vision-01，编号保留给现有检具。新设备需唯一编号及专用配置包，不能只改 IP。

尚未实现

多来源、新格式与主动上传

当前仅有一个 dataFile 自动读取入口；多来源汇集、其他型号与测点结构的通用解析，以及 HTTPS 上传仍需开发验证。

范围与容量一起确认只采集普通 backup，排除 _ALLmeasure 与 failure；结果写到独立的 data/vision.json。当前单批输入及门户已存记录最多 20,000 条，输入及存储文件最多 128 MB，两类上限同时适用，不是每台各有一份容量。

文件有效、无采集错误且仍可读，但扫描时间超过默认 2 小时，页面显示“共享可读取，等待采集更新”，继续提供查询和自动刷新。读取失败、内容损坏或采集报错仍显示真实异常；等待提示不能证明采集仍在运行。

七步接入：每一步都留下可核对的结果

  1. 1

    现场负责人

    收集设备资料和真实样例

    • 列出线体、检具名称、型号、台数，一台填一张信息表。
    • 确认结果软件、普通 backup 路径、日期目录及文件名结构；相机图像和点云不能代替检测结果。
    • 准备正常与实际 NG 样例；有缺测、复检等情况时，补对应真实样例。没有的情况标“待补样”，不编造。
    • 将设备地址、网络区域和现场、IT 联系人交给授权维护人员。

    交付：设备资料表、实际样例和待确认事项。

  2. 2

    门户管理员

    登记检具，分配唯一设备编号

    在“视觉检具 → 登记检具”填写线体名、检具名、编号、共享或上传方式、路径、型号、测点数及备注。路径不确定时标为待维护确认，选择上传只代表计划。

    • vision-01 保留给现有检具；新设备使用新编号。
    • 一机一号，后续升级或改 IP 保持原编号。
    • 不要在任何登记字段中填写密码。

    交付：待配置台账。出现卡片或选择项不表示已经接通。

  3. 3

    维护人员，必要时联系供应商

    验证数据格式，生成设备专用配置包

    核对实际型号、测点数量和名称、SN、时间、数值、缺测写法与整体、逐项判定。单位或判定规则不清楚时先查证。

    每台包绑定自己的编号、源目录和输出目录。其他型号不能套用现有 61 项规则；现有 v2 包也不能直接复制用于多机。

    新增第二个自动来源前，需先完成多来源读取或汇集；用新路径覆盖现有 dataFile 并不等于同时接入两台。

    交付：已验证样例、专用采集包及服务端接入方案；未适配设备保持待配置。

  4. 4

    现场人员与生产网络 IT

    持续采集，只共享独立结果目录

    按专用包说明先采集一次，再启动持续采集并保持运行。输出目录位于源 backup 之外，由程序生成 data/vision.json；只共享结果文件夹。

    IT 核对共享和文件权限，必要时建立专用非管理员读取账号。密码由用户在 Windows 中自行输入，不发聊天，不写进脚本或页面。检具生产程序原有写入权限需保留。

    跨网段访问由 IT 核对；同一 Wi-Fi 不保证可达。现有 v2 默认输出今天和昨天，补历史需另行规划容量。

    交付：更新中的输出文件、授权读取方式和运行负责人。

  5. 5

    维护人员与生产网络 IT

    在最终部署服务器上验证

    使用门户服务实际运行的身份读取共享，核对文件更新、扫描时间和错误状态。个人电脑能打开文件夹，不代表服务账号可读。

    厂内 Windows 由服务器读共享、浏览器看网页；云部署先完成上传或专用网络方案，当前没有现成上传开关可启用。

    路径仅作占位示意：\\<检具主机名或地址>\<采集结果共享名>\vision.json，不能照抄。

    交付：最终服务器、最终服务账号下通过的读取或接收记录。

  6. 6

    现场负责人和维护人员

    先验收一台，包含重启恢复

    按下方验收表比对原软件与网页，并检查新检测更新、复检去重、来源不串数据。维护时段内验证检具与门户服务器重启后的采集、网络、认证和服务恢复。

    缺少某类实际样例时记录“待验证”；没有做过重启测试时，不宣称可无人值守长期运行。

    交付：有日期、责任人及未完成项的单台验收记录。

  7. 7

    门户管理员，现场与维护人员共同确认

    分批启用其他检具

    单台验收通过、多来源能力完成后，再按线体分批启用。每台保留唯一编号、专用配置和验收记录；每批复核来源、最近更新和整体容量。

    交付：逐台确认的接入清单。未完成适配的设备继续待配置。

单台验收清单

  • 同一 SN 的时间、整体 OK/NG、测点名称、数量和关键数值与原软件一致。
  • 逐项 NG 与整体判定分别保留，测点合格率不替代零件合格率。
  • 重复文件不重复计数，同 SN 不同时间的复检可区分。
  • 切换线体、检具后来源正确，多台同 SN 不会串数据。
  • 新增实际检测后，采集输出、扫描时间、网页记录依次更新。
  • 采集暂停或共享不可读时显示相应等待或异常，旧数据不被当作最新。
  • 已在维护时段验证两端重启后的采集、网络、认证与服务恢复。
  • 无实际样例的 NG、缺测等情况标为待验证；容量、历史保留和联系人已确认。

前提条件与局限性

本流程以获得授权、提供实际检测结果样例，以及现场、维护人员和 IT 能够配合为前提。已适配的前副车架接入不代表任意品牌、型号或台数都能直接使用。登记不会突破当前单来源、格式及容量限制。

部署形式确定后，需在最终环境重新验收。本指南是接入分工与交付说明，不代表已完成其他设备的数据连接、多来源接口、上传接口或开机自动启动。
