# 工艺部业务门户

以拓普蓝为主色、多色图表辅助区分的本地业务工作台，包含管理员登录及四个入口：补焊周报、补焊实时监控、安灯报警、定位销与伸缩气缸管理。管理员首次配置数据源后，后台自动取数，日常只需登录门户。

## 本地运行

前提：电脑安装 Node.js 22 或更新版本，且能访问业务系统网络。

1. 将 `config.example.json` 复制为 `config.local.json`，由系统维护人员填写 API 地址、网页地址、登录参数和前后副物料组。公开版本只提供占位配置。
2. 在项目目录运行 `npm run setup`，设置本机管理员账号和密码。密码输入不显示，仅保存加盐摘要；公开源码没有默认账号密码。
3. 运行 `npm start`，或者在 Windows 双击 `启动门户.cmd`。
4. 浏览器打开控制台显示的本机地址，用本机管理员登录，即可进入四个功能；CSV 清单校验不要求公司连接。
5. 首次使用时由管理员打开“数据源设置”，填写有权限的公司业务系统账号；验证成功后加密保存在本机。服务重启、门户登录后会自动连接，公司会话过期时自动更新，无需每次手动连接。
6. 使用结束后退出门户；重启服务后需重新登录门户，已保存的数据源会自动恢复。更换 Windows 用户或迁移机器时需重新配置数据源。

这是本地运行服务，不能通过双击 `public/index.html` 完成数据连接，也没有部署到互联网。无需安装第三方运行依赖。

## 功能与口径

- **补焊周报**：默认全部物料、线体和缺陷，缺陷多选留空表示全部；前副和后副只是快捷物料组，不会把默认范围限制到两个产品组或“焊偏/焊穿”。缺陷空值归为“未填写”。可按产品快捷组、线体、缺陷多选和关键词筛选，图表与明细使用同一批筛选记录。展示日志条数、涉及件数、条/件、位置 Top 5、产线分布、动态各线 OP 占比和已读取区间的五周趋势。重复日志保留；涉及件数按“非空物料编码＋非空二维码”组合去重，缺少任一字段的日志仍计条数但不计件数。各线 OP 占比以该线全部筛选后日志为分母，已知 OP 前五名之外和未识别工位合为“其他”。日期区间是统计依据，未把企业 KW 编号硬套为 ISO 周；未读取的历史不会自动补齐。
- **补焊实时监控**：当天累计和最新记录；周报与实时页均默认每 30 秒刷新，可暂停或改为 15/60 秒；页面隐藏时暂停。当天范围跨日自动推进。这是定时读取，不是服务器推送，日志数不能据此认定已完成补焊。
- **线体识别**：优先接口明确线体字段，再使用维护人员配置的已核对规则；已核对的 11–14 线二维码规则仅限配置的前副/后副物料。其他记录仍计入统计，无法确定线体时显示待识别，不能将某料号直接视作唯一线体。支持 `weldLineFields` 和 `weldLineRules` 扩展。
- **安灯报警**：以待响应、处理中、待复线三栏卡片展示待处理报警，辅以线体进度矩阵、部门分布、趋势和排行，支持日期、线体/区域、进度、负责小组和归口部门筛选。每张卡片对应一条报警，同设备的多条报警分别保留；队列来自全部已取得且符合筛选的记录，不受当前明细分页限制。阶段时间分别取来源中的有效创建、响应、解决时间；缺失、已知时序倒置或未来时间显示待核实，不推算或显示负持续时间。已完成与状态待核实记录单独计数，不混入三栏。未闭环且有有效解决时间才列为待复线，有响应证据列为处理中，已完成以原系统闭环标记为准。有效复线时间与未闭环标记冲突时列为“状态待核实”。部门仅根据维护人员配置的 `alarmDepartmentRules` 匹配指定字段；按报警类别归口是统计配置，不是接口原生部门或正式组织归属，不替换原负责小组。未匹配或规则冲突保留“部门待确认”。显示响应、处理和复线时长及有效样本量；不以假定生产工时计算 MTBF。三栏是报警处理队列，不代表全部设备的即时状态，也不表示所选创建日期之外的全部历史待办。
- **定位销与伸缩气缸管理**：主视图以备件卡片展示名称、库存、状态和库位，可展开规格与编号等详情、切换台账。缺货与低库存优先，支持库存状态筛选；汇总基于分页前全部已取记录。数量可能属于不同规格或计量单位，不适合简单相加；汇总卡统计备件记录条数。库存不按录入日期过滤。
- **入库清单本地校验**：支持 CSV UTF-8，校验必填项、正整数数量、重复、类型和公式风险，输出预览与准备文件。当前不支持 XLS/XLSX，不写入生产库存。原系统台账导入与入库流水是两个接口，尚未核验当前账号的正式入库权限。

配置口径：`alarmDepartmentRules` 支持按负责小组匹配的 `{department, groupPattern}`，或按指定字段匹配的 `{department, field, pattern}`；例如 `field` 可设为报警类别字段 `mainType`。`alarmDepartments` 仅声明希望常显的部门名称，不会自动给记录分配部门。示例配置中的部门及线体规则均为空，不预置真实归属。安灯线体先用明确的 `productionLine/lineName`，再按 `alarmLineRules` 中同时匹配区域与设备的规则取首个命中，最后保留原 `line` 区域；每条记录仍保留原区域及识别来源。

局限性：真实连接依赖有效账号、相应模块权限和网络可达性。代码的模拟测试不能替代公司环境联调。源系统没有提供稳定分页快照，取数期间记录变动可能影响统计；数量变化、日期异常、分页上限会明确标记部分数据。有观测时统计已读取记录，不能据此证明数据完整；没有观测且未确认完整覆盖的历史日期、周或已配置部门显示缺失，不补零。只有覆盖完整且确实没有匹配记录时，才允许显示 0；不生成不具备可比性的环比。当前最大查询区间为 42 天，默认每次最多读取 50 页（每页 200 条），建议从较短区间开始。

## 本地文件与公开源码

`config.local.json` 仅留在使用者电脑，不加入版本控制。管理员密码仅存随机盐与 scrypt 摘要；数据源凭据保存在忽略目录 `runtime/` 的 Windows DPAPI 密文中，绑定当前 Windows 用户。浏览器不会收到公司密码或令牌。也可通过 `PORTAL_SOURCE_USERNAME` / `PORTAL_SOURCE_PASSWORD` 环境变量配置，环境变量优先；非 Windows 环境不回退明文保存。

业务令牌与成功数据缓存留在服务内存，由已授权的门户会话共用。浏览器仅保留本机 HttpOnly 会话标识。公司令牌过期后仅重登并重试一次；权限不足不反复登录。网络连接失败退避，明确认证失败或连续失败会暂停并提示管理员。切换数据源账号后，旧请求不得回填新账号的数据。

服务只监听回环地址，拒绝跨站请求，仅开放已核验的三个业务读取接口。退出门户不清除后台的自动连接配置；关闭服务清除内存令牌，再启动会用加密配置自动建立新连接。若正式部署，需要提供可访问公司网络的主机，并重新配置该主机的数据源；公开 GitHub 仅保存代码，不提供公司数据访问。

公开仓库不包含公司地址、账号密码、真实业务记录、原网站下载的源代码样本或本地接口核对资料。品牌图仅用于本项目界面展示；仓库公开不授予品牌商标的使用许可。

## 开发与验证

```sh
npm test
npm run setup
npm start
```

前端为 `public/` 下的原生 HTML/CSS/JavaScript；`server.cjs` 提供本机登录和读取服务；`lib/auto-source.cjs` 管理自动连接，`lib/credential-store.cjs` 管理本机加密凭据；`lib/source.cjs` 适配业务系统协议；三个 report 模块执行纯统计；`lib/import-preview.cjs` 仅校验清单。测试全部使用人工构造的记录和模拟业务系统，不会调用公司系统或修改生产数据。

后续开放正式入库前，需要核对备件主键、入库字段、权限和防重复提交规则，并以用户确认的具体清单进行提交。
