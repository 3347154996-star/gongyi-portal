# 工艺部业务门户

以拓普蓝为主色的本地业务工作台，包含工号登录、补焊点、安灯报警、备件管理、视觉检具和工具中心。公司业务数据源由管理员首次配置；视觉检具统一读取公司尺寸检测报表，支持组合筛选及一键报告；工具中心提供焊接参数导出、检具与三坐标对比。

## 本地运行

前提：电脑安装 Node.js 22 或更新版本，且能访问业务系统网络。

1. 将 `config.example.json` 复制为 `config.local.json`，由系统维护人员填写 API 地址、网页地址、登录参数和前后副物料组。公开版本只提供占位配置。
2. 仅首次新部署在项目目录运行 `npm run setup`，设置本机管理员账号和密码。迁移已有门户时保留原配置与成员库，不重新初始化。密码输入不显示，仅保存加盐摘要；公开源码没有默认账号密码。
3. Windows 双击 `启动门户.cmd`，服务在后台启动并自动打开网页；重复双击会打开已经运行的同一门户。免安装包自带 Node，完整解压后即可使用，不需要运行安装或校验命令。
4. 用本机账号登录；视觉检具复用公司数据源连接；工具中心和 CSV 清单校验不要求公司连接。需要开发控制台时仍可使用 `npm start`。
5. 首次使用时由管理员打开“数据源设置”，填写有权限的公司业务系统账号；验证成功后加密保存在本机。服务重启、门户登录后会自动连接，公司会话过期时自动更新，无需每次手动连接。
6. 双击 `停止门户.cmd` 结束通过新启动器运行的服务。关闭浏览器或退出账号不会停止后台门户；重启服务后需重新登录门户，已保存的数据源会自动恢复。更换 Windows 用户或迁移机器时需重新配置数据源。

如需在登录页显示一批新成员的统一初始密码，先为对应成员设置该密码，再复制 `public/login-help.example.txt` 为 `public/login-help.local.txt`，填写 `initialPassword` 并设置 `enabled: true`。这个文件只控制提示，不创建账号、不重置密码，也不改变已修改密码的账号；未配置、禁用或读取失败时不显示提示。实际值仅保存在部署电脑，文件已被 Git 忽略，迁移时按内部资料管理。提示及该文件可被任何能访问门户的人读取，只用于明确同意公开给门户访客的初始密码，不能填写管理员密码或其他秘密。关闭提示时设置 `enabled: false` 并清空 `initialPassword`，或移除本地文件，然后刷新页面；已看到提示的访客仍可能记住旧值。成员登录后可在“设置 → 修改密码”自行更换。

这是本地运行服务，不能通过双击 `public/index.html` 完成数据连接，也没有部署到互联网。无需安装第三方运行依赖。

手机端已适配小屏布局，当前回环地址仍只能在运行服务的电脑上访问。手机入口需要管理员配置可信 HTTPS、网络可达性和来源校验；部署步骤与实机验收边界见 [手机访问与部署](docs/手机访问与部署.md)。目前仅完成浏览器模拟视口验证，尚未完成真实手机验收。

视觉检具当前链路为“现场检具上传公司 MES → 门户服务器只读查询 → 浏览器”，不再依赖共享目录或现场采集文件。内网服务器部署时，需要保证服务器能访问公司系统，并在该服务器配置有读取权限的公司账号；配置与查询口径见 [公司尺寸接口接入](docs/公司尺寸接口接入.md)。换机时的私有文件、凭据重配、只读对账及历史文件保留要求见 [当前 MES 部署迁移与历史共享盘方案](docs/共享盘中转与迁移.md)。此处仅针对视觉检具；熔深仍使用其独立配置的共享表来源。

`PORTAL_VISION_DATA_FILE`、`vision.dataFile` 与采集中转不参与当前 MES 查询。`npm run vision:check` 已改为提示历史用途并以非零状态退出；历史维护须显式使用 `npm run vision:check:legacy`，即使结果成功也只代表旧采集文件检查通过，`mesVerified: false`，不能当作 MES 连通。旧采集查询、导入和台账入口在通过身份与请求校验后返回 HTTP 410；保留旧程序及历史文件不代表这些入口仍可用。

## 功能与口径

- **公司尺寸检测**：视觉检具从公司工序报表读取已上传记录，动态发现尺寸检测线体。时间与数量二选一：按时间读取所选时段全部记录，按数量读取跨日期的最近 N 次；支持线体、设备、物料、检测结论和工件码筛选。原始整件 OK/NG 用于合格率，同 SN 复测按不同记录 ID 分别计数；可查看测点值、上下限与 NG。页面可见且未打开详情或报告时每 60 秒刷新。记录不完整、判定未知或工序混合时不显示确定合格率；仅查看 OK/NG 或单件时不显示整线合格率。

- **统一工作台**：统一导航、按钮、筛选区、面板与小屏布局。补焊概览、分析与记录可直接跳转，详情和统计口径按需展开。筛选草稿与已应用条件分离，状态轮询不重建结果；按账号在当前标签会话中保留查询条件，退出清除。备件列表分页并将选中项核对区前置；来源不支持的操作明确禁用。后续模块遵循 [界面规范](docs/界面规范.md)。
- **工具中心**：焊接参数导出支持 ABB RAPID 备份解析、任务筛选、Excel/CSV 导出；检具与三坐标对比支持原工具格式的 Excel 报告匹配、偏差分析和结果 HTML 保存。两项工具在浏览器本地处理文件，不依赖外部 CDN，不上传文件。已提供版本化注册表、输入输出契约及浏览器适配器，远端处理明确保持禁用；详见 [工具扩展接口](docs/工具扩展接口.md)。原工具的格式假设与换算系数仍需结合现场设备核对。
- **视觉检具**：只读取公司已上传的尺寸检测记录，支持线体、物料、设备、时间（精确到分钟）或最近数量二选一，并与检测结论、工件码等条件组合筛选；图表与一键报告使用相同的已应用范围。采集文件切换、CSV 导入和共享盘后台读取已停用，历史文件保留。接口与部署前提见 [公司尺寸接口接入](docs/公司尺寸接口接入.md)。
- **补焊点**：默认全部物料、线体和缺陷，缺陷多选留空表示全部。物料下拉按原系统物料名称精确筛选，可用本地配置 `weldMaterialNames` 固定选项及顺序；无配置时列出当期已读取的名称。配置项目在当期没有日志时仍保留，来源读取完整时显示 0，否则不显示确定条数；“全部物料”始终包含全部已读记录。切换物料会恢复全部线体，线体选项随所选物料更新。缺陷空值归为“未填写”。可组合物料、线体、缺陷多选和关键词筛选，图表、趋势与明细使用同一批筛选记录。展示日志条数、涉及件数、条/件、位置 Top 5、产线分布、动态各线 OP 占比和已读取区间的五周趋势。重复日志保留；涉及件数按“非空物料编码＋非空二维码”组合去重，缺少任一字段的日志仍计条数但不计件数。各线 OP 占比以该线全部筛选后日志为分母，已知 OP 前五名之外和未识别工位合为“其他”。日期区间是统计依据，未把企业 KW 编号硬套为 ISO 周；未读取的历史不会自动补齐。
- **补焊点实时刷新**：默认每 30 秒刷新，可暂停或改为 15/60 秒；页面隐藏时暂停。当天范围跨日自动推进。这是定时读取，不是服务器推送，日志数不能据此认定已完成补焊。周报不再作为独立入口。
- **缺陷明细**：点击缺陷类型可查看该类型在线体、OP 工位和规范化缺陷位置上的分布。层级统计使用全部已取得且符合当前条件的日志，明细分页不影响统计；各级占比以父级日志数为分母，涉及件数分别去重，不跨分支相加。未识别工位、未填写位置仍保留并计入总量。可从层级定位对应原始记录，工位与位置按规范化值精确匹配，界面显示可清除的定位条件。弹窗保留打开时的数据快照，不因后台刷新关闭。
- **原始缺陷分类**：父类取日志中的 `badness_type`，细类取 `badness_content`；只按日志里已观察到的父类 ID 读取原系统对应的内容字典，成功结果在当前数据源会话缓存一小时。完整分类展示已取得的字典选项，不代表所有选项都在本次发生。未观测分类仅在日志完整性已核对时显示 0，否则显示未见记录；字典获取失败仍保留正常日志统计。字典中的“断焊/未满焊”等合并项保持原名和单项计数，没有证据时不继续细分。
- **线体识别**：优先接口明确线体字段，再使用维护人员配置的已核对规则；已核对的 11–14 线二维码规则仅限配置的前副/后副物料。相同数字线号按已配置前副、后副分别统计，例如“11线前副”和“11线后副”。接口已有完整线体名称时保留原名。无法确定物理线体的记录按产品分别显示“线体待确认”，完整计入总量，但不算已识别线体；产品名不等同于唯一物理线体。支持 `weldLineFields` 和 `weldLineRules` 扩展。
- **安灯报警**：以待响应、处理中、待复线三栏卡片展示待处理报警，辅以线体进度矩阵、部门分布、趋势和排行，支持日期、线体/区域、进度和部门筛选。每张卡片对应一条报警，同设备的多条报警分别保留；队列来自全部已取得且符合筛选的记录，不受当前明细分页限制。阶段时间分别取来源中的有效创建、响应、解决时间；缺失、已知时序倒置或未来时间显示待核实，不推算或显示负持续时间。已完成与状态待核实记录单独计数，不混入三栏。未闭环且有有效解决时间才列为待复线，有响应证据列为处理中，已完成以原系统闭环标记为准。有效复线时间与未闭环标记冲突时列为“状态待核实”。部门仅根据维护人员配置的 `alarmDepartmentRules` 匹配指定字段；按报警类别归口是统计配置，不是接口原生部门或正式组织归属；界面只按部门展示，不显示来源中的小组维度。未匹配或规则冲突保留“部门待确认”。显示响应、处理和复线时长及有效样本量；不以假定生产工时计算 MTBF。三栏是报警处理队列，不代表全部设备的即时状态，也不表示所选创建日期之外的全部历史待办。
- **备件管理**：按工艺部清单读取公司实时库存，支持成员工号登录、扫码/照片识码、入库、出库、盘点和指定人员复核。相同编号的型号与库位逐条保留；缺编号可补贴绑定仓库来源的二维码。已适配动力部 UDP 协议与公司 Mold 入库、台账修改协议；当前工艺部使用 Mold，出库因原页面提交方式尚未核实而保持禁用。现场连接与操作权限需单独验收；手机访问需配置可信 HTTPS，现场核对资料仅保留在本机。
- **设置**：独立的个人账号与成员权限入口。成员管理由管理员在此完成，不再附属于备件模块；普通成员可查看自己的账号并修改密码。
- **入库清单本地校验**：支持 CSV UTF-8，校验必填项、正整数数量、重复、类型和公式风险，输出预览与准备文件。当前不支持 XLS/XLSX，不写入生产库存。原系统台账导入与入库流水是两个接口，尚未核验当前账号的正式入库权限。

配置口径：`alarmDepartmentRules` 支持按负责小组匹配的 `{department, groupPattern}`，或按指定字段匹配的 `{department, field, pattern}`；例如 `field` 可设为报警类别字段 `mainType`。`alarmDepartments` 仅声明希望常显的部门名称，不会自动给记录分配部门。示例配置中的部门及线体规则均为空，不预置真实归属。安灯线体先用明确的 `productionLine/lineName`，再按 `alarmLineRules` 中同时匹配区域与设备的规则取首个命中，最后保留原 `line` 区域；每条记录仍保留原区域及识别来源。

局限性：真实连接依赖有效账号、相应模块权限和网络可达性。代码的模拟测试不能替代公司环境联调。源系统没有提供稳定分页快照，取数期间记录变动可能影响统计；数量变化、日期异常、分页上限会明确标记部分数据。有观测时统计已读取记录，不能据此证明数据完整；没有观测且未确认完整覆盖的历史日期、周或已配置部门显示缺失，不补零。只有覆盖完整且确实没有匹配记录时，才允许显示 0；不生成不具备可比性的环比。当前最大查询区间为 42 天，默认每次最多读取 50 页（每页 200 条），建议从较短区间开始。

## 本地文件与公开源码

`config.local.json` 仅留在使用者电脑，不加入版本控制。管理员密码仅存随机盐与 scrypt 摘要；数据源凭据保存在忽略目录 `runtime/` 的 Windows DPAPI 密文中，绑定当前 Windows 用户。浏览器不会收到公司密码或令牌。也可通过 `PORTAL_SOURCE_USERNAME` / `PORTAL_SOURCE_PASSWORD` 环境变量配置；任意一项存在即优先使用环境变量，必须成对配置，不完整时不会回退本机凭据。在环境变量管理期间，页面不能覆盖或清除凭据，须由维护人员修改后重启；非 Windows 环境不回退明文保存。

业务令牌与成功数据缓存留在服务内存，由已授权的门户会话共用。浏览器登录凭据仅使用本机 HttpOnly 会话标识；查询偏好保存在按账号区分的 sessionStorage 中，不缓存业务结果。公司令牌过期后仅重登并重试一次；权限不足不反复登录。网络连接失败退避，明确认证失败或连续失败会暂停并提示管理员。切换数据源账号后，旧请求不得回填新账号的数据。

服务默认只监听回环地址，拒绝跨站请求，仅开放已核验的业务模块、尺寸检测报表和字典查询。退出门户不清除后台的自动连接配置；关闭服务清除内存令牌，再启动会用加密配置自动建立新连接。若正式部署，需要提供可访问公司网络的主机，并重新配置该主机的数据源；公开 GitHub 仅保存代码，不提供公司数据访问。

公开仓库不包含公司地址、账号密码、真实业务记录、原网站下载的源代码样本或本地接口核对资料。品牌图仅用于本项目界面展示；仓库公开不授予品牌商标的使用许可。

## 开发与验证

```sh
npm test
npm run setup
npm start
```

前端为 `public/` 下的原生 HTML/CSS/JavaScript；`server.cjs` 提供本机登录和读取服务；`lib/auto-source.cjs` 管理自动连接，`lib/credential-store.cjs` 管理本机加密凭据；`lib/source.cjs` 适配业务系统协议；三个 report 模块执行纯统计；`lib/import-preview.cjs` 仅校验清单。测试使用人工构造的记录和模拟业务系统；运行 `npm test` 的前提是使用不含私有配置/凭据的隔离副本，并在测试子进程环境中清除继承的 `PORTAL_*` 业务环境变量，尤其 `PORTAL_PENETRATION_DIRECTORY`，避免部分服务测试触发实际熔深目录扫描。无需修改生产进程的环境配置。

离线验证仅在上述无私有配置、无继承业务环境变量的条件下使用隔离测试；`npm start`、`启动门户.cmd` 和 `startup-diagnostics.cmd` 会实际启动服务，可能恢复已配置的公司自动连接与熔深共享表扫描，不能当作离线检查。前提与局限：离线测试通过不证明 MES 可达或记录完整；目标主机须由授权维护人员按迁移文档分别核对公司会话、目录、列表、详情和同范围记录，不执行库存操作来验证连接。

可通过 `npm start` 启动本机门户；合成演示由 `node test/preview-inventory.cjs` 启动。真实入库与调账必须以明确物料、库位和数量核对；当前测试通过不代表生产过账已验收。现场验证记录仅保留在本机，不上传公开仓库。

## 隔离界面验证

`test/check-vision-*.cjs` 使用临时目录、合成数据和本机隔离服务。运行需另行提供 Playwright 与可用的 Edge 浏览器；默认解析 `playwright` 包，也可通过 `VISION_PLAYWRIGHT_PATH` 指定本机模块路径。该工具依赖不属于生产运行依赖。自动单元测试运行 `npm test`，采集器测试可运行 `python -m unittest discover -s collector -p "test_*.py"`。

公开版本不包含本机配置、业务数据、实际检具台账、现场截图、采集EXE或本机诊断脚本。首次部署要由管理员在部署主机配置数据源及权限，现有前副车架条目也不能单独证明新环境已连通。

## 熔深共享表与公司周

新增熔深模块，按月或公司周查看快切已判定焊缝合格率、全切异常反馈及复检结果。2026/10/02–10/08 为 KW41（周五至周四）。全切没有总检测分母，不计算首次合格率。`privacy.productNames: "original"` 按来源原名展示产品、筛选与详情，不推断不同命名属于同一产品；示例配置使用此模式。旧配置未填写该项时仍保持 `alias` 代号模式，修改后重启服务。真实名称、历史代号映射和共享路径不进入仓库。接入配置、自动更新、统计边界和迁移要求见 [熔深接入与名称显示](docs/熔深接入与保密显示.md)。

视觉检具新增测点分析：应用筛选后点击“加载全部测点”，支持 NG 帕累托、测点排行、整件 OK/NG 环图、测点实际值趋势和统计值。横轴可选时间或 SN，适用时显示 Pp/Ppk 及 I-MR 估计控制界限，提供独立测点报告的 PDF 打印和 HTML 下载。每次最多分析 1000 次检测，必须完整取得所选记录的全部详情；查看分析期间暂停自动刷新，结束分析后恢复。公式、显示条件与局限性见 [公司测点统计口径](docs/公司测点统计口径.md)。
