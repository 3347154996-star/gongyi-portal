# 视觉检具普通检测数据采集

本模块读取 BaseV3 已保存的 CSV，生成供门户读取的 JSON，不修改检具源文件，也不连接检具生产数据库。现有前副车架检具已通过“现场采集 → 只读结果共享 → 门户”的方式接入；提供 Python 源码及 Windows 64 位免安装 v2 工具。实际是否持续更新，以采集状态和门户最后扫描时间为准。

## 采集范围

按确认的路径读取：

```text
D:\BaseV3\ReleaseEXE\backup\Tesla_Front11\日期\*.csv
D:\BaseV3\ReleaseEXE\backup\Tesla_Front12\日期\*.csv
```

只允许上述两个普通型号，同时校验文件名与文件内 PartName。不会采集 Tesla_Front11_ALLmeasure、Tesla_Front12_ALLmeasure、failure。日期文件夹会自动发现，不固定为某一天。首次运行读取范围内已有历史文件；后续扫描只解析新增或有变更的文件。

2026-10-13 现场共享验收时，Front11 与 Front12 的已接收普通检测记录均为 61 项。格式不符的文件会报告错误，不会悄悄套用另一套格式；供应商更改格式或新增型号后仍需重新验证。

## 运行前提

- 运行源码需要 Python 3.10 或更新版本，不需要额外安装 Python 软件包；使用 Windows 免安装 v2 EXE 时不需要另装 Python。
- 运行账户能够读取上述 backup 目录，且检具继续生成同结构的完整 CSV。
- 把程序放在独立目录，例如 `D:\VisionCollector`；采集输出也必须位于源 backup 目录之外。
- 下列采集命令在程序所在目录的 PowerShell 中执行。如果 `python` 命令不可用，需要改为实际 Python 路径。EXE 使用方法见[免安装版使用说明](免安装版使用说明.txt)，保持持续采集窗口运行；本次门户部署改造不要求更换现场 EXE。

## 先读取一次

```powershell
python .\vision_ingest.py collect --source-root 'D:\BaseV3\ReleaseEXE\backup' --device-id 'vision-01' --recent-days 2 --progress
```

这会生成程序目录下的两个文件：

- `data\vision.sqlite`：采集模块自己的数据库，保存已读取的记录和去重信息。
- `data\vision.json`：网页后端可以读取的数据，包含记录、汇总和最近一次扫描状态。

`vision-01` 是设备标识。同一台设备以后保持不变；不同设备使用不同标识。上述 D 盘路径是检具电脑上的路径，需要在检具电脑上运行。不能在另一台电脑上直接用该路径读取检具文件。

## 持续读取

确认首次读取结果后，可运行：

```powershell
python .\vision_ingest.py collect --source-root 'D:\BaseV3\ReleaseEXE\backup' --device-id 'vision-01' --recent-days 2 --progress --watch
```

程序每轮扫描完成后等待 5 秒。有新文件时，先等待 3 秒并核对文件大小、修改时间是否稳定，读取前后再次核对。发生变化的文件留到下轮处理。按 Ctrl+C 停止。这不是开机自动启动服务，也不能保证精确的 5 秒更新时延。

未完成或格式不符的文件不会入库，下轮仍可重试。不能只看旧的 JSON 判断采集正常，应同时检查其中 `last_scan.scanned_at_utc` 是否更新，以及 `errors`、`deferred`。日志时间和 JSON 扫描时间分别使用文件里的本地时间、UTC 时间，不能直接按字符串对比。

v2 默认只扫描和导出今天、昨天的记录，更早已入库的记录保留在 `data/vision.sqlite` 中，不随本次近期 JSON 全量输出。上面的源码命令显式采用相同窗口；省略 `--recent-days` 会使用全部历史范围，不能不评估门户容量就用作补历史操作。现有 EXE 固定 `vision-01`，不可直接复制给多台检具。

## 采集逻辑验证

在门户项目根目录运行：

```powershell
python -m unittest discover -s collector -p "test_*.py"
```

这会运行采集逻辑测试，不会启动现场持续扫描。测试通过不能代替真实现场的格式、权限及重启恢复验收。

## 网页接入约定

JSON 中 `records` 是检测记录，主要字段如下：

| 字段 | 含义 |
| --- | --- |
| device_id / part_name | 设备标识 / 普通检测型号 |
| serial_number | 零件 SN |
| measured_at_local | CSV 内检测时间；尚无已验证的时区信息 |
| source_result | CSV 的整体 OK 或 NG |
| measurements | 61 项测量记录，按 name 识别项目，不依赖行位置 |
| identity_conflict | 同设备、型号、SN、时间出现不同内容，需核对 |
| warnings | 缺失数值、判定差异等核对提示 |

每个测量项目包含 name、nominal、lower_limit、upper_limit、is_critical、deviation、source_result。Dev 保留为“偏差 Dev”，单位未知，不擅自添加 mm，也不统一按 Nominal + Dev 还原实测尺寸。NaN 以 JSON 的 null 表示，保留原文本并添加提示。

整体判定和逐项判定均保留 CSV 原值。额外的 `range_comparison` 只是 Dev 与上下限的数值比较，不替代原判定。`unit` 当前为 null。

完全相同的记录重复扫描或复制不会增加检测次数；同一个 SN 的不同时间记录会保留。相同设备、型号、SN、时间而内容不同的记录会全部保留并标记冲突，暂不计入合格率，不能自行选其中一条。

`summary.pass_rate` 为 0 到 1 的比例，分母是本次导出范围内未发生身份冲突的检测记录数。它统计检测次数，不是当天产量，也不是去重后的零件数；使用近期窗口时不是全部历史汇总。门户按已经保存的记录和页面筛选条件另行统计。`total_records` 含冲突版本，`eligible_records` 是参与合格率统计的记录数。

门户自动读取本程序输出的 JSON，现有现场共享已接入；新服务器仍须单独配置和验收权限。门户侧保留 `vision.dataFile`，设置环境变量 `PORTAL_VISION_DATA_FILE` 后优先覆盖；空白值会报配置错误，不回退旧路径。只填写文件路径，不含凭据。Windows 使用 UNC，并授权实际服务身份；Linux 或容器先由 IT 受控只读挂载 SMB，再配置挂载后的绝对路径，不直接使用 UNC 字符串。

门户服务独立后台同步，即使无人查看也会运行；页面读取缓存。门户端 `vision.pollIntervalSeconds` 默认 30 秒、范围 5–3600 秒；`vision.readTimeoutMs` 默认 10000 毫秒、范围 1000–60000 毫秒。同一服务实例的同步不重叠，读取超时或无效文件保留旧记录并提示异常。以上设置不改变采集程序的扫描间隔或近期输出窗口。

门户读取期限不能取消底层 SMB 调用：超时后保留同一在途读取防止堆积，底层返回后后续轮次才能继续；持续不返回时需恢复系统连接，必要时重启门户并核对数据，不保证所有断网都自动恢复。

部署人员在门户目录以同一服务身份、相同配置环境执行 `npm run vision:check` 做只读自检，不写真实业务数据，不打印记录、源路径或凭据。共享文件传输与网页访问相互独立：服务器读取 SMB 文件，电脑和手机访问门户 HTTPS。采集程序不启用 HTTP 服务，不主动上传；网页监听、TLS、权限及开机启动由部署人员另行配置验收。

完整步骤见[视觉检具接入](../docs/视觉检具接入.md)与[其他检具接入流程](../docs/其他检具接入流程.md)。系统行为依据见 [Microsoft：Services and Redirected Drives](https://learn.microsoft.com/en-us/windows/win32/services/services-and-redirected-drives) 与 [Ubuntu：mount.cifs](https://manpages.ubuntu.com/manpages/noble/man8/mount.cifs.8.html)。

## 验证与局限性

已对所提供 Front12 CSV 完成离线解析，并使用合成样例验证全检排除、重复读取、重复 SN、冲突记录、中文、NaN、异常格式和源文件内容不变。测试只使用样例，不代表已经验证现场持续采集、网络可达性或长期性能。

解析器当前只接受已确认的七列、61 项格式。未来供应商改变格式、测点数量或编码时需要调整。仅靠大小和修改时间稳定不能证明供应商已经完成整个检测流程；当前同时要求 CSV 完整且结构有效，现场仍需对比一批检测结果与备份生成时机。历史文件量很大时，全目录扫描与完整 JSON 输出可能变慢，需要在正式接入时测量并优化。

后台同步不能自动补齐停机期间的历史。门户停机或共享中断超出今天、昨天快照窗口时，可能漏接已退出窗口的记录，短于两天也需核对跨日边界。门户单批输入和已存记录上限为 20,000 条，输入及存储文件上限为 128 MB；达到限制需安排归档或扩展，不能只增加输出范围。迁移应带上门户 `runtime` 历史记录和检具台账，保留现场 `data/vision.sqlite` 及原 CSV，用于维护人员按日期和容量受控补接；当前不自动从现场 SQLite 回补，也不应为迁移删除旧库。
