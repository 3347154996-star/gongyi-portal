# 视觉检具接入

视觉检具是现有工艺部业务门户的第四个模块，入口为 `/#vision`，沿用原门户工号登录。它不需要公司补焊、安灯数据源处于已连接状态。成员可查询，管理员可导入普通检测 CSV。

## 数据范围与口径

仅接受 Tesla_Front11、Tesla_Front12 普通检测；带 `_ALLmeasure` 的全检和 failure 不采集。结构包括 SN、时间、整体 OK/NG，以及 61 项测量值、公差、关键点标志和逐项结论。2026-10-13 现场共享验收时，两个型号的已接收记录均为 61 项；这不代表供应商未来改变格式后仍无需重新验证。

以设备标识、型号、SN、时间识别一次检测；不同时间的同 SN 复检保留，相同内容重复导入不增加次数。同次检测有不同内容时保留所有版本并标注冲突，暂不计入合格率。页面按筛选后的全部记录统计，分页只影响列表。统计的是检测次数，不能直接当成去重零件产量。

整体与逐项判定保留来源值；Dev 显示为偏差，不推算绝对尺寸，不擅自认定单位。缺测值显示缺失。CSV 中的本地时间保持原样，不凭文件名推定时区。已读取记录不能证明现场历史完整。

## 合格率曲线、时间与最近数量

“今天”“近7天”“近1个月”“全部”会同时更新统计、曲线与记录列表，并保留型号、检测结论、SN 和最近数量条件。近7天与近1个月都包含今天，近1个月明确按最近30天计算。快捷范围为开始日 00:00 至结束日 23:59，结束分钟的全部秒均包含在内；也可手动选择日期、小时和分钟。快捷日期以查看网页的电脑本地日期为准，现场使用时需与检具日期一致。开始或结束留空表示该侧不限时间。接口仍兼容日期型参数，日期型起止分别对应 00:00 与 23:59。

“查看数量”可选全部、最近100条、500条、1000条或自定义1–20000条。在时间、型号、结论和 SN 条件筛选后，按检测时间倒序取最新 N 条；同时间按记录 ID 稳定排序。页面注明符合条件数量和实际取用数量，不足 N 条时使用实际条数。这里统计检测记录而非去重 SN 数，同一零件重复检测按多条计数。总体指标、各粒度曲线和分页列表均使用同一批选中记录；翻页不改变统计。冲突识别基于全部已保存记录，即使另一个冲突版本未进入筛选或最近 N 条范围，也不把已选版本当作正常记录。

统计间隔可选自动、5分钟、15分钟、30分钟、1小时、1天。自动模式在明确设置同一天的起止时间时按15分钟分组，其他情况按天分组。分组使用检具原始本地时间，向下取整到固定时段起点，不改变记录时间。例如10:07开始、15分钟间隔的首桶仍为10:00，但只包含10:07及以后的选中记录；按最近 N 条截取也可能形成部分首尾时段。每个点为该时段 OK 次数 / 可统计次数，冲突版本排除；总体合格率按全部选中次数计算，不取各时段合格率的平均值。检测结论筛选也参与统计，因此只筛 OK 时合格率会是100%，只筛 NG 时会是0%。

曲线纵轴固定0%–100%，每10个百分点显示刻度。无记录或无可统计结果的时段不连接、不补零，只有一个有效时段时显示单点。鼠标在绘图区内移动会选择横向最近的真实点，立即显示时间段、合格率、OK/NG及可统计次数；指针移动只更新本地提示和标记，不发送查询或重建整张图。触屏可点击，键盘可聚焦点并用左右方向键、Home/End切换，Enter/空格查看，Escape收起浮层；也能展开完整分段数据表。低于10次检测的时段有样本量提示，较细间隔造成的波动需结合检测次数解释。

可查看的历史范围取决于已经接入并保存在门户的记录；选择近1个月或最近1000条不会自动补采缺失的历史。

## 多线体与检具登记

网页已提供线体、检具筛选和管理员登记表。现有前副车架检具使用 vision-01；新检具可登记新线体、独立编号、计划连接方式、来源路径、型号和测点数量。登记保存在本机 runtime/vision/catalog.json，只记录待配置资料，不访问新路径、不自动建立采集。已配置检具禁止被待配置资料覆盖。待配置范围不显示其他检具记录或曲线。台账按单服务实例写入设计，最多100台，包含现有检具。

实际新增线体仍需维护人员适配型号、测点格式和多来源读取；当前采集与读取只支持已核验的普通 Front11/12。完整步骤和厂内部署迁移说明见[其他检具接入流程](其他检具接入流程.md)，门户中也可打开可打印的“接入流程”。部署地点尚未确定，共享读取与云端上传的前提分别列出，云端上传尚未实现。

## 文件导入

登录后进入“视觉检具”，管理员选择普通检测 CSV，并填写稳定的设备标识。每次可导入一份文件；重复文件自动去重。这个操作只保存到门户的 `runtime/vision/`，不会向检具数据库、公司库存或原 CSV 写回。

导入后显示文件记录，不能据此称现场已经实时连接。未收到现场新数据时，不会自动生成任何检测结果。

## 自动读取采集结果

现场电脑无法调用 Python 时，可使用已经打包的 Windows 64 位“视觉采集工具.exe”。启动器源码为 `collector/vision_portable.py`，无参数双击显示中文菜单：1 近期采集一次，2 持续采集，0 退出。v2 默认扫描和导出今天及昨天（`--recent-days 2 --progress`），更早的已存记录保留在数据库里，不整库输出。它将数据放到 EXE 旁的 `data` 文件夹，默认源目录仍为 `D:\BaseV3\ReleaseEXE\backup`。此方式不需要额外安装 Python；详细步骤见 `collector/免安装版使用说明.txt`。网页仍需配置共享路径以读取该 JSON。

采集程序位于本门户的 `collector/vision_ingest.py`，需要 Python 3.10 或更新版本。门户本身沿用 Node.js 22 或更新版本，不新增第三方软件包依赖。

若门户运行在检具电脑上，进入门户目录后运行：

```powershell
python .\collector\vision_ingest.py collect --source-root 'D:\BaseV3\ReleaseEXE\backup' --device-id 'vision-01' --database '.\runtime\vision-collector.sqlite' --output '.\runtime\vision-input.json' --recent-days 2 --progress --watch
```

采集程序只读普通检测日期目录，原始 backup 不作为输出位置。窗口需保持开启，Ctrl+C 可停止。上述命令仅扫描并输出当天和前一天；之后处理范围内新增或改变的文件。跨日时按检具电脑的本地日期更新范围，设备时钟需正确。未指定 `--recent-days` 的原始命令仍保留全部历史读取方式，补历史应另行安排容量。`vision-01` 同一设备保持不变，不同设备使用不同标识。

网页定时请求时会读取 `runtime/vision-input.json` 并合并新记录。JSON 更新时使用临时文件替换，格式或校验失败时保留上次有效数据，并报告读取异常。

## 门户与检具在不同电脑上

已实现的跨电脑方式是读取经过授权的 Windows 共享路径，可以选择其中一种：

1. **门户电脑直接读 CSV 共享。** 检具电脑把所需 backup 目录提供只读共享，门户电脑运行采集程序。将上述 `--source-root` 改为真实的共享路径，例如 `\\检具电脑IP\共享名`；输出仍位于门户本机 runtime。
2. **检具电脑运行采集程序。** 输出到独立的采集结果目录，再把该目录提供只读共享。门户维护人员将私有 `config.local.json` 中的 `vision.dataFile` 设置为真实 JSON 的 UNC 路径。例：`"vision": {"dataFile": "\\\\检具电脑IP\\共享名\\vision.json"}`。这是示意地址，不能照抄为实际配置。

前提是两台电脑实际可达、共享已配置，运行程序的 Windows 用户有读取权限。连接同一 Wi-Fi 不足以证明这些条件满足。该模块不会创建共享、修改防火墙、保存共享密码或自动开放门户到局域网；使用系统已有的文件访问权限。不要把整个检具硬盘开放共享。

当前现场使用第二种方式，实际共享路径只保存在本机私有配置中，凭据由 Windows 管理。采集窗口需保持“持续采集”运行；共享可读取不代表采集正在更新，页面会显示最后扫描时间。现场验收记录保留在本机，不纳入公开仓库。重启电脑后的认证和网络恢复需在最终部署主机验收；局域网 HTTP 推送和开机启动服务尚未实现。

## 维护与验收

- 重启门户后登录，确认导航出现“视觉检具”。旧服务进程不会自动载入新后端代码。
- 首先核对已知 SN 的整体判定、61 项数值和时间，再核对一批 OK、NG、复检和异常文件。
- 验证同一个文件重复读取只计一次，全检目录无记录，跨日新目录可被采集。
- 中断共享或改为无效输入，页面应提示异常；不能把旧数据误当最新采集。
- 页面中的检查时间是门户读取时间，不代表检具最后检测时间。完整性和设备时钟仍需现场核对。

源文件格式变化、长期大数据量、网络中断与恢复尚需现场验收。当前单批输入与本地记录上限为 20,000 条，输入和存储文件上限为 128 MB；达到上限会保留已有数据并报错，需要先安排归档或扩展存储，不能视为长期容量承诺。门户当前合并存储文件与采集输入使用完整 JSON，历史量大时需要测量读取和筛选时间，再考虑增量接口或独立数据库。

默认采集扫描宽限为2小时（7200秒）。共享文件仍可读取、内容有效且无采集错误，但扫描时间超过宽限时，页面显示中性状态“共享可读取，等待采集更新”；不按断连处理，不置灰统计，不停止查询或自动刷新。扫描时间再次更新后自动恢复正常。没有新零件但扫描时间持续更新时也保持正常。扫描时间缺失、非法、明显超前，采集报错或文件实际读取失败时仍明确显示异常并保留已保存记录。维护人员可用 `vision.maxScanAgeSeconds` 调整阈值，范围为30–86400秒；已设置的有效值继续生效。未覆盖该配置时使用2小时默认值。该判断以前后电脑时钟基本一致为前提；共享可读不能证明采集程序正在运行，等待状态仍展示最后扫描时间供核对。
