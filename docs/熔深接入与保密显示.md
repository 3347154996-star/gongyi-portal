# 熔深共享表、公司周与名称显示

## 接入与更新

门户后台以当前 Windows 账号读取 UNC 共享目录，浏览器和手机只访问门户接口。部署到服务器时，给运行门户的账号授予同一共享目录的读取权限；Linux 应先由管理员挂载共享目录，再填本机挂载路径。不要把共享盘账号、密码或真实目录写入前端或 GitHub。

`config.local.json` 配置示例（实际路径只放本机）：

```json
{
  "penetration": {
    "directory": "\\\\YOUR_FILE_SERVER\\YOUR_SHARE\\2026年",
    "year": 2026,
    "pollIntervalSeconds": 3600,
    "scanTimeoutMs": 180000
  },
  "privacy": { "terms": [] }
}
```

也可用 `PORTAL_PENETRATION_DIRECTORY` 覆盖目录。后台扫描该年度下“全切熔深新版反馈汇总表”和“快切支架熔深新版反馈汇总表”的 `1月` 至 `12月` 文件夹，最多向下两层，支持 `.xlsx`、`.xls`，跳过临时锁文件、符号链接及其他目录。“报废明细”“验证件”不纳入此统计。

启动时同步，此后每小时检查变化；新增月目录、保存后的新增或修改工作簿自动进入下一次同步，页面也可“同步最新数据”。不是只在月初执行一次。关闭浏览器不影响后台；停止门户期间不更新。读取使用独立子进程，默认超过 180 秒终止本轮；可将 scanTimeoutMs 调至最高 300000（300 秒）以适应首次年度扫描。失败保留上次可用缓存，并明确标记失败及覆盖诊断。原有月份或类别突然变空时保留旧数据并标记不完整，避免网络异常被误认为检测数归零。首次年度同步较大时，将已解析文件保存在本机检查点；下一次复用未变化的文件，检查点不会冒充已完成统计。只有全轮无读取失败时才推进完整同步成功时间。解析规则升级后，旧规则记录须重读才能进入统计；更换共享来源不会显示另一来源的旧缓存。不要在共享文件未保存时认定网页反映最新修改。

`npm run penetration:sync` 会只读共享原表，并更新本机熔深缓存与产品代号台账；它不是无副作用的只读状态检查。不要与运行中的门户同时执行此命令，以免两个进程争用本机缓存。

XLSX 使用 ZIP 目录和定点读取，只提取工作簿表格 XML，不传输嵌入图片；XLS 读取完整文件。不执行宏或单元格公式，只读已保存结果。单文件最大 512 MiB（旧式 XLS 最大 64 MiB），提取 XML 合计最大 64 MiB，每轮最多 500 个文件，缓存最多 64 MiB；超过限制会显示不完整，不能悄悄截断当作全量。

## 统计口径

- **快切首次已判定焊缝合格率**：初检 `OK / (OK + NG)`。`NG1`、`NG2` 归为 NG；空白或无法识别的判定单独列为“未判定”，不算合格，也不进入该分母。这里按焊缝记录统计，不等于产品件数或产线总合格率。
- **全切异常反馈**：用户确认没有完整检测总表，因此只统计不合格反馈；全切首次合格率显示“—”。原件复切、补切及调试结论独立保留，不覆盖首次结论。子目录中的独立全切检测报告属于明细附件，不与异常反馈汇总重复计数，也不能当作全量检测总表；已识别的附件报告单列排除数量，无法确认的格式仍标为读取失败。
- **模板与日期**：仅预填日期/焊缝编号、没有判定或实际检测证据的行排除。旧年份、其他月份的模板不按文件夹名或修改时间强行归入当前月份。按表内检测日期归属；缺日期不猜测，日期存在歧义时显示诊断。数字 `1.1` 在未保留显示精度时无法证明原录入者是否想表达 `1.10`，需要原表人工修正。
- **重复与冲突**：具备日期、产品/线体、钢印码、焊缝编号时用语义键识别副本；矛盾版本排除统计并提示。缺钢印码时保留来源行身份，不能保证跨文件副本完全去重。不同真实复测若复用全部身份字段，也可能需要人工核对冲突。
- **产品分组**：必要时组合原表线体和部件名称，避免不同产品共用泛称而被合并。原名模式展示这个来源名称，不另取 P 代号；不同来源命名不擅自认定为同一产品。显示方式变化不会改变原有分组或统计数值。

来源是已经读取且符合表头约定的反馈表，无法证明所有现场检测都已登记。无数据、未接入、不完整、没有检测分母与零不合格必须区分。首次接入与新增模板应由业务人员对照原表核对，不能把解析成功当作业务完整性证明。

## 公司周

已确认的锚点：**2026-10-02 至 2026-10-08 = KW41**，周五至下周四。10 月 9 日至 15 日为 KW42。补焊图表、补焊/报警日期快捷查询、光学检具和熔深共用 `public/company-calendar.js`；不能只换标签而保留 ISO 周一分桶。

跨年暂采用“包含 1 月 1 日的周为 KW01”，与上述锚点相容，但尚未得到公司跨年周历确认。跨年周若涉及另一年度、而另一年度数据未接入，当前年度结果只覆盖已接入日期，不能宣称完整周。

## 名称显示与迁移

本机配置 `privacy.productNames: "original"` 时，页面、筛选和详情保留来源原名，工具新导出结果也使用原名。不修改原表、历史记录或统计身份；已存历史代号筛选由服务器按现有映射恢复后查询。此模式不再声称对产品、文件名或已知名称进行隐藏，门户访问权限和公司网络要求仍适用。

可选 `privacy.productNames: "alias"` 继续让服务器在返回 JSON 前，将结构化产品名称、型号、文件名/共享路径及已识别名称在其他文本中的出现转换为固定代号。为兼容旧部署，缺少该配置时保持代号模式；示例配置已明确使用原名模式。配置修改后重启服务。代号及原名称映射保存在忽略目录 `runtime/product-aliases.json`，不下发完整映射，不提交 GitHub。切换原名时保留这个文件用于旧筛选兼容，不重写台账；它与 `config.local.json`、其他业务缓存仍仅在本机管理。

代号模式下，已识别结构化字段会自动登记；`privacy.terms` 用于补充只出现在设备名、备注、规格等自由文本中的保密词。未知自由文本没有通用的产品语义识别保证：新增产品、缩写、别名或数据模板应更新本机词库并验收。原名模式不应用这份保密词库。

两项本地文件工具默认保留导入文件中的原名，处理不依赖服务器上传；页面、名称搜索、新导出的 CSV/XLSX/HTML 保持同一名称策略。它们可独立选择代号模式，与服务器配置及产品台账不联动，详见工具扩展接口文档。原文件及历史下载文件不会追溯改写；已经只存代号且没有反向映射的旧结果无法恢复原名，需要重新导入源文件。

搬家时复制整个门户目录及本机 `runtime`、`config.local.json`，保留代号台账才能维持同一代号。先停止门户再复制。新电脑仍需 Node.js 22+、公司内网和共享盘读取权限；公司系统加密凭据可能需重新配置。

## 依赖与来源

表格解析固定使用官方 SheetJS CE 0.20.3，随代码携带 Apache-2.0 许可，无需运行时联网下载。[官方安装文档](https://docs.sheetjs.com/docs/getting-started/installation/nodejs/)与[读取选项](https://docs.sheetjs.com/docs/api/parse-options/)。

Windows 服务应使用 UNC 路径并配置运行账号权限，不能假设交互用户的映射盘符对服务可见，见 [Microsoft 服务与重定向驱动器说明](https://learn.microsoft.com/en-us/windows/win32/services/services-and-redirected-drives)。
