# 工具中心与扩展接口 v1

两个工具由用户提供的完整 HTML 整合而来。门户的工具中心位于 `/#tools`，工具分别在新标签页打开：

| 工具 ID | 入口 | 输入 | 输出 |
| --- | --- | --- | --- |
| `weld-export` | `/tools/weld-export/index.html` | ABB RAPID 备份文件夹或 `.mod / .sys / .txt` | Excel 两工作表、CSV、剪贴板；对应当前筛选结果 |
| `measurement-compare` | `/tools/measurement-compare/index.html` | 现场检具与三坐标 `.xlsx / .xlsm` 报告 | 按点位或工件对比，保存包含全部本地组件的离线 HTML |

文件内容仅在当前浏览器页面内处理。服务端不接收报告字节、不持久化工具结果、不自动同步。关闭页面会丢失未导出的结果。用户主动保存的报告可能包含业务数据，应按现有内部文件规范保管；不应提交进源代码仓库。

## 名称显示与已有结果

两个工具默认显示导入文件中的原名称。程序名、触发信号、焊接数据名、文件名、工作表名和混合文字工件编号在页面、搜索、复制及导出中采用同一名称策略。解析、工件配对、任务隔离、工程点位和数值换算不随显示策略改变。CSV / 剪贴板仍处理公式前缀，HTML 显示仍转义文本；Excel 中名称以文本单元格保存。

本地工具独立于门户的 `config.privacy.productNames` 设置，离线报告不查询门户产品目录。部署确需旧代号模式时，可在 `privacy.js` 加载前由同源外部脚本设置 `window.ToolPrivacyOptions = { anonymizeNames: true }`；缺省或其他值均使用原名称。不要用 inline 脚本绕过门户 CSP。代号模式只影响显示和导出，其代号不是加密，也不提供反向原名映射。契约的 `displayPrivacy.version: "local-names-v2"`、`defaultMode`、`optionalMode` 描述这一策略。

新保存的对比 HTML 包含当次结果中的原名称，可离线重开。已有结果若保存了原名称，当前工具会保留；若只保存了旧代号且无原名映射，则继续显示这些代号，不凭相似编号猜测原名。重新导入原始报告可按原名称生成结果。已下载的旧 HTML 内含当时版本的脚本，本次网页更新不会自动改写这些本机文件。

## 服务端发现接口

以下路由沿用门户现有会话鉴权；没有会话返回 401。未知工具返回 404。

- `GET /local/tools`：返回 `version`、`processing: "browser"`、`uploadsEnabled: false` 和 `tools` 数组。每个工具包含 `id`、`title`、`description`、`entry`、`inputs`、`outputs`、`version`、`remote`。
- `GET /local/tools/v1/{toolId}/contract`：返回版本、输入/输出 JSON Schema、大小限制、适用前提、本地适配器说明和远端接口状态。
- `POST /local/tools/v1/{toolId}/run`：预留但禁用，返回 501，错误码 `tool_adapter_disabled`。现版本不读取、转发或保存上传内容。修改前端按钮或请求体不能开启该能力。

实现入口为 `lib/tools.cjs` 的 `createToolsService()`，方法为 `manifest()`、`contract(id)`、`runRemote(id)`。返回的结构都是副本，调用方不能修改全局配置。

契约版本采用语义化版本；破坏输入、字段含义或计算口径的变更应新增版本。输入 Schema 描述文件**元数据**，不是可上传报告的协议；实际字节绑定为浏览器 `File[]`。未来服务端处理需单独设计二进制传输、授权、留存周期与审计，不能把元数据接口误当作已有上传接口。

## 本地适配器

同源工具页通过 `public/tools/bridge.js` 暴露 `window.PortalToolBridge`：

```js
PortalToolBridge.version;                 // "1.0.0"
PortalToolBridge.capabilities();          // processing: browser, remoteEnabled: false
await PortalToolBridge.importFiles('weld-export', input.files);
const result = PortalToolBridge.getResult('weld-export');
PortalToolBridge.reset('weld-export');
```

`importFiles` 接受页面上用户选择的 FileList / File 数组；焊接文件应保留 `webkitRelativePath` 以识别 TASK。不读取任意本机路径。检具工具每次最多 2 个文件，也可先后导入。结果为当前页面数据的深拷贝，未导入时返回空结果或 null。

- 焊接结果：`{version, headers, rows, rowCount}`。每行 15 列，依次为序号、任务、过程、主程序状态、触发信号、行号、标签、welddata 名、seamdata 名、速度 mm/s、速度 IPM、焊接模式、电压 V、电流 A、原始 welddata。
- 检具结果：原工具完整计算结构，含 `items`（点位方向及配对数值）、`pairs`（工件配对）、`diagnostics`（未配对/重复/缺失原因）、`unit: "mm"`、`formula` 及原有统计字段。

完成导入/比较后，在**当前窗口**触发 `portal-tool:result`：

```js
window.addEventListener('portal-tool:result', ({detail}) => {
  // detail: {version, toolId, processing, fileCount?, rowCount?, pairCount?, itemCount?}
});
```

事件只带非负整数计数，不携带文件名、本机路径、工件编号或原始数据。接口没有 postMessage、跨窗口通知、网络传输或浏览器存储。`runRemote()` 总是拒绝并给出 `tool_adapter_disabled`。

新增工具可复用 `shared.css` 和工具导航栏，在 `lib/tools.cjs` 登记清单与 Schema，并注册 `{importFiles, getResult, reset}` 适配器。所有可执行脚本必须使用本地外部文件，通过 `addEventListener` 绑定事件；不要增加 inline 事件或降低全站 CSP。

## 原有功能与修正

焊接工具保留任务隔离、主程序启用/注释识别、参数筛选、模式名称、缺失参数筛选和所有原有导出。整合时修复重复导入后旧主程序/模式残留、文件夹拖入只读取首批目录项、无剪贴板 API 的异常、动态 inline 按钮与门户 CSP 冲突。输入文本显示进行 HTML 转义；CSV / 剪贴板文本处理公式前缀。Excel 导出改为本地 OOXML 写入器配合 JSZip，保留两工作表，不再请求 CDN。

检具工具保留完整 XLSX 解析、前导零编号处理、复测保留、歧义配对拒绝、理论值修正、图表、阈值筛选及离线 HTML 保存。数值型长编号的精度检查同时覆盖科学计数表示；文本编号保持原值。门户页面加载本地外部脚本；保存结果时只 GET 当前应用的同源静态组件，合并进下载文件，不上传用户报告。下载副本去掉依赖门户路径的返回入口，避免离线死链接。已保存 HTML 再次保存不需要联网。文件限制提示统一为解析器实际的单文件 64 MB；解压前检查 ZIP 声明大小（单项 100 MiB、合计 200 MiB），解压时逐块复核实际大小，超限或与声明不一致即停止读取。

第三方组件 JSZip 3.10.1 来自用户提供的检具工具，包含 Pako。保留原版权头，并附完整 MIT 许可（`public/tools/vendor/JSZip-LICENSE.md`、`pako-LICENSE.txt`）；许可文字也写入 JSZip 文件，随离线导出保留。没有新增生产 npm 依赖。

## 前提条件与局限性

- 焊接规则与换算系数沿用原工具，适用于其支持的 ABB RAPID 方言、`PROC / ArcLStart` 和 `TASK PERS welddata` 格式。没有完整解释执行机器人控制程序，也不证明实际设备电流单位；投产前应与设备配置和原备份核对。
- 默认启用判断来自 `MainModule.mod` 中的直接 `WL_…` 调用，不覆盖所有可能的间接调用、动态程序名或控制流。缺少主模块时会提示查看全部，而不会把未识别程序认定为已启用。
- 检具工具适配原工具支持的横向报表模板，不是任意 Excel 的通用映射器。宏不执行、公式不重算；只使用已保存的数值。理论值差超过 0.1 mm 的项目不会自动比较。
- 文件夹选择与拖入依赖浏览器支持；不支持时可选择单个/多个文件。多个无路径文件会归入 `(root)`，无法凭空恢复 TASK 目录。
- 远端适配器、自动归档、设备写回均未接通。不要将预留路由或 Schema 描述解释为已部署的业务能力。

## 验证

`node --test test/tools.test.cjs test/tool-privacy.test.cjs` 验证本地解析、状态重置、完整目录遍历、XLSX 结构、编号匹配、理论值差、歧义处理、默认原名/可选代号策略、结果保存与旧代号兼容、适配器数据边界和 CSP 静态约束。服务端鉴权与路由测试在 `test/server-tools.test.cjs`。浏览器应额外验证文件选择、下载、离线报告重开、窄屏及真实设备输入；单元测试不能代替这些用户操作。
