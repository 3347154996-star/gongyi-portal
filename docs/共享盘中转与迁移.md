# 共享盘中转与 Windows 门户迁移

本方案把门户迁到另一台 Windows 电脑，当前电脑继续中转检具数据。前提是两台电脑能访问公司指定共享目录，当前电脑仍能读取现场采集文件；共享地址和运行账号由部署人员在本机配置。本文不包含真实共享路径、账号、密码或检测记录。

## 数据链路

```text
现场检具：普通 CSV → 现有采集程序 → 采集 JSON
                                  ↓ 只读
当前电脑：中转程序 → 公司共享目录中的完整 JSON
                                  ↓ 只读
新电脑：门户自动读取 → 新电脑本地 runtime 历史记录 → 浏览器
```

现场采集程序保留原来的设备标识、数据目录和输出方式。当前电脑负责读取采集 JSON 并发布到公司共享目录；新电脑通过 `vision.dataFile` 或优先级更高的 `PORTAL_VISION_DATA_FILE` 读取共享 JSON。两项设置只填写文件路径，不填写共享账号或密码。Windows 使用完整 UNC 路径，不依赖个人登录会话映射的盘符。

中转必须保留原记录、设备标识和 `last_scan.scanned_at_utc`。复制成功时间不代表现场刚刚完成扫描，不得用当前时间改写扫描时间。每次应先完整读取、校验并写入共享目录中的临时文件，再替换正式文件；失败保留上一份正式文件，不用空文件覆盖。中转只需发布采集输出，不发布门户成员、配置、密码或整个 `runtime`。

`runtime/vision/records.json` 是门户历史存储，不能直接充当现场采集 JSON；两者元数据用途不同。共享目录仅作数据传输桥梁，门户运行目录和 `runtime` 放在新电脑本地，不让两台门户同时写同一份存储。

## 迁移文件清单

程序包应保留 `server.cjs`、`package.json`、`启动门户.cmd`、`setup-admin.cjs`、两个连接检查脚本，以及完整的 `lib/`、`public/`。包括内置第三方库及许可证；不可只复制首页。文档、测试与 `collector/` 可随包保留，门户运行不需要安装 Python。

以下私有文件应从停写后的同一份快照转移到新目录，保持相对路径：

| 文件 | 用途及迁移要求 |
| --- | --- |
| `config.local.json` | 管理员摘要、业务连接和规则配置。保留原内容，只修改已确认的部署项；不要用示例配置覆盖。 |
| `runtime/members.json` | 成员、角色、启用状态和密码摘要。保留后原账号密码继续有效。 |
| `runtime/inventory-scope.json` | 工艺部备件范围，缺失时不能扩大为全公司库存。 |
| `runtime/inventory.json` | 如存在，必须保留库存操作、幂等请求和未知结果，不能以空文件替代。 |
| `runtime/product-aliases.json` | 原名模式仍用于兼容历史代号筛选，保留旧台账。 |
| `runtime/vision/records.json` | 已接收的检具历史，不能只带最新采集快照。 |
| `runtime/vision/catalog.json` | 如存在，保留新增检具登记台账。 |
| `runtime/penetration/cache.json` | 已解析熔深记录及覆盖诊断。 |
| `runtime/penetration/pending.json` | 如存在，可保留未完成扫描的进度缓存。 |
| `public/login-help.local.txt` | 如需延续本机登录提示，一并私有转移；它可能含登录页显示的密码提示。 |

原本不存在的可选文件不需要创建空文件。配置若引用项目目录以外的库存范围或 TLS 证书、私钥，还需单独转移或重新配置这些文件。私有文件不上传公开 GitHub，也不作为公共网页附件发布。

`runtime/source-credentials.dpapi.json` 是旧 Windows 用户保存的公司系统连接密文，不作为新电脑可直接使用的登录凭据。旧机保留备份；新电脑由实际运行门户的 Windows 用户重新设置公司连接，或由维护人员提供受控环境变量。不要尝试把密文转成明文放进脚本或交接提示词。

运行包不需要 `.git`、开发输出、日志、诊断报告、临时文件及测试样本。命名核对工作簿和旧备份可在原机另行保留。只有在确认源门户已停止写入后，才在目标副本中排除 `inventory.lock`、`inventory-recovery.lock` 和未完成的临时文件；不得删除正在运行的源程序锁文件。

## 启动与切换

将 `vision-relay.example.json` 复制为被 Git 忽略的 `vision-relay.local.json`，在中转电脑填写实际的 `sourceFile` 与 `destinationFile`。`node vision-relay.cjs --once` 执行一次校验转发；`node vision-relay.cjs --watch` 持续转发，按 Ctrl+C 停止。每轮完成后等待 `intervalSeconds`，单轮超过 `timeoutSeconds` 会终止工作子进程，确认退出后才允许下一轮，避免共享挂起时不断叠加任务。

可另开终端执行 `node vision-relay.cjs --stop`，它通过本机实例标识请求当前中转停止，不直接结束任意 PID。中转仅允许同一运行目录单实例；异常关机留下锁时，由维护人员确认该目录对应实例已经退出后再处理锁。随包 Node 存在时，`启动门户.cmd` 优先使用 `portable-node/node.exe`；不需要安装 npm 依赖。

1. 新电脑安装 Node.js 22 或更新的受支持版本，确认 `node --version` 可用。当前项目没有第三方 npm 安装依赖；已有采集 EXE 自带运行时。只有直接运行采集 Python 源码时才需要 Python 3.10+，且只使用标准库。
2. 安排短暂停写，停止旧门户并备份私有文件，再复制到新电脑。旧电脑继续承担中转，不同时提供库存写入入口。新旧目录都保留独立本地存储，避免共享写入或回滚覆盖新交易。
3. 用实际运行中转的 Windows 账号确认现场读取与公司共享写入权限；用实际运行新门户的账号确认共享读取权限。交付包中的中转启动、停止入口及私有配置用法，以对应脚本说明为准；配置完成前不要声称中转已接通。
4. 在新电脑配置桥接 JSON 的完整路径。检查是否存在 `PORTAL_VISION_DATA_FILE` 环境变量覆盖预期配置。公司系统凭据若使用 `PORTAL_SOURCE_USERNAME`、`PORTAL_SOURCE_PASSWORD`，必须成对配置，它们优先于本机凭据文件。
5. 在门户目录运行 `npm run vision:check`。该命令只读校验连接、格式和扫描时间，不导入记录，不输出源路径或凭据。必须与以后运行门户使用同一 Windows 身份和配置环境。
6. 双击 `启动门户.cmd` 或运行 `npm start`，按终端提示访问本机地址并用已有门户账号登录。迁移已有成员库时不要重新执行 `npm run setup`，否则改动初始管理员可能与成员库不匹配。
7. 核对历史数量、最新扫描时间、产品筛选及各模块读取后完成切换。不要通过提交真实库存操作来代替只读连接验收；生产过账需另行按现场流程核对。

`启动门户.cmd` 是前台启动方式，需保持窗口打开；在启动窗口按 `Ctrl+C` 停止，再按提示确认。中转使用其交付的停止入口；不要在写入过程中直接删除共享文件。当前入口不等同于 Windows 服务或开机自启，若要常驻，需要单独配置运行身份、开机任务和恢复策略，并在重启后复验。

门户账号密码采用随机盐和 scrypt 摘要，不绑定 Windows；迁移后需要重新登录，因为旧会话仅在进程内存中。公司系统凭据采用 DPAPI `CurrentUser`，通常要求原用户及原电脑，漫游配置属于例外，不能作为迁移前提。依据：[Microsoft DPAPI](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)。共享盘符按登录会话划分，服务身份应使用 UNC 并具备明确权限。依据：[Microsoft Services and Redirected Drives](https://learn.microsoft.com/en-us/windows/win32/services/services-and-redirected-drives)。

## 历史与故障边界

现有现场采集输出窗口为今天、昨天。门户停机或中转中断后，已退出窗口的记录不会自动补回；中断不足两天也需要按跨日边界核对。迁移必须带门户历史记录，现场 SQLite 和原 CSV 保留原地，用于必要的受控补接；不可清空旧库后只接最新 JSON。

门户单批输入和累计检具记录上限均为 20,000 条，输入及存储文件上限为 128 MiB。中转不提高这些上限，也不自动归档。文件可读取只能证明当前链路可用，不能证明历史完整。保持两端时钟正确；旧扫描即使刚复制到共享盘，仍应显示为旧扫描。

门户默认每轮完成后间隔 30 秒读取，读取超时默认 10 秒，失败保留已有记录；超时不会取消底层 SMB 调用。底层调用迟迟不返回时，需要恢复系统连接，必要时重启门户并核对，不能保证任意断网都自动恢复。

熔深缓存按来源目录字符串和年份绑定。迁移尽量保持原 UNC 写法；改成盘符或另一种等价路径会使旧缓存不再复用，需重新扫描。库存连接的地址、仓库和协议也参与来源身份判断，不能为迁移随意改动或合并。

## 手机访问

迁移不自动开放手机访问。默认门户只监听新电脑回环地址；手机中的 `localhost` 指手机本身。手机入口需要公司可达网络、对应域名或地址的受信任 HTTPS 证书、`tls.certFile` / `tls.keyFile`、准确的 `publicOrigins` 和限定访问范围的防火墙规则。

若使用反向代理，当前实现要求后端也启用 TLS，并保留外部 `Host` 和原始 `Origin`；不能仅靠 `X-Forwarded-Proto` 把现有 HTTP 后端当作 HTTPS。部署在域名根路径。详见[手机访问与部署](手机访问与部署.md)。真实手机还需验收登录、相机授权、文件选择与下载，电脑或模拟视口通过不能代替这些检查。
