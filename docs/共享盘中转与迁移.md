# 当前 MES 部署迁移与历史共享盘方案

本文保留原文件名以兼容旧链接。适用前提：使用 `codex/mes-dimensional-report` 分支的当前实现；视觉检具读取公司 MES 中已经上传的检测记录。迁移时应核对实际部署版本，不能把本文套用到仍运行采集文件模式的历史版本。

当前视觉检具的数据链路是 **现场检具上传 MES → 门户服务器通过公司账号只读查询 MES → 浏览器显示与报告**。共享盘中转、采集 JSON、`PORTAL_VISION_DATA_FILE` 和旧采集检查都不是当前视觉检具部署的前置条件。旧采集程序及文件继续保留历史维护价值，不因本次文档修正而删除。

局限性：本说明依据仓库代码及离线测试，不代表目标服务器已经连通公司系统，也不证明现场全部检测都已上传。公司环境只读验收由获授权维护人员另行执行；不能用库存过账验证迁移。本文不包含实际内部地址、账号、密码或检测记录。

## 当前数据链路与入口

```text
现场检具 ──既有上传流程──→ 公司 MES 检测记录
                              ↑ 只读查询
浏览器 ──门户登录──→ 门户服务器 /local/vision/mes/*
                     └─ 已保存的公司数据源账号与会话
```

门户服务器本身必须能访问公司 MES；浏览器只需能访问门户。检测报表由 `public/vision-mes-report.js`、测点分析由 `public/vision-mes-analysis.js` 发起请求，经 `server.cjs` → `lib/auto-source.cjs` → `lib/source.cjs` → `lib/vision-mes-report.cjs` 读取。对应本地接口为 `/local/vision/mes/catalog`、`report`、`detail`、`analysis`；历史不合格参数查询由 `public/vision-mes.js` 经 `processes`、`lookup` 使用 `lib/vision-mes.cjs`，不能替代检测报表统计。

这些本地 MES 业务接口仅接受 GET，复用门户的公司数据源凭据。采集文件的 `/local/vision/catalog`、`report`、`import`、`records` 及记录子路径，在通过门户身份与请求校验后返回 HTTP 410。未登录或来源不合法的请求仍先被认证或来源校验拒绝。当前服务不启动旧采集文件轮询，不把本地历史导入 MES，也不会在 MES 读取失败时回退到共享 JSON。

| 配置或命令 | 当前用途与验收边界 |
| --- | --- |
| `config.local.json` 中的公司地址、登录参数及 `vision.mes` | 当前 MES 数据源与查询配置；详见 [公司尺寸接口接入](公司尺寸接口接入.md)。 |
| `PORTAL_SOURCE_USERNAME` / `PORTAL_SOURCE_PASSWORD` | 由运行服务的进程读取，优先于本机 DPAPI 凭据；必须成对设置。 |
| `vision.dataFile` / `PORTAL_VISION_DATA_FILE` | 仅供历史采集适配器使用；不配置 MES，不影响当前 MES 查询，也不能重新启用已停用入口。 |
| `npm run vision:check` | 旧命令名仅提示历史用途并以非零状态退出；不作为当前部署检查。 |
| `npm run vision:check:legacy` | 显式检查历史采集文件，结果标记 `mode: "legacy-file"`、`mesVerified: false`。即使成功也不证明 MES 登录、目录、列表或详情可读。 |
| `npm run penetration:sync` | 熔深共享表检查与本地同步；与视觉检具 MES 连接无关。 |
| `npm test` | 在无私有配置/凭据、已清除继承 `PORTAL_*` 业务环境变量的隔离副本运行；使用合成数据、模拟公司接口和隔离本机服务，不能证明真实连接成功。 |

MES 检测结果、公司令牌、列表/详情缓存和分析快照保存在服务内存中；当前实现不把 MES 记录累积到 `runtime/vision/records.json`。服务重启或换机后需要重新登录门户；公司会话变化或缓存过期后需要重新查询列表，旧分析快照不可迁移。已下载的 HTML/PDF 报告是内部资料，只是某次查询快照，不是可恢复 MES 的数据库备份。

## 迁移前保留的文件

以下相对路径均以含 `server.cjs` 的程序目录为基准；若交付包使用 `app/` 目录，它就是程序目录。完整保留当前版本的 `server.cjs`、`launch-portal.cjs`、`package.json`、启动/停止入口及 `lib/`、`public/`，包括内置库与许可证。源码或不含 Node 的包需要 Node.js 22+；若交付包包含 `portable-node/node.exe`，启动入口优先使用它。没有第三方 npm 运行依赖，MES 门户也不需要 Python。

先停止旧门户并确认退出，制作私有文件的同一时点备份；复制后在目标首次启动前核对文件清单、大小及哈希。不要用新版本的示例配置覆盖已有配置，不要让两台门户共同写一份 `runtime`。新旧本地目录各自保留独立存储，切换时保持旧机停写。

| 本地文件 | 迁移要求 |
| --- | --- |
| `config.local.json` | 保留初始管理员摘要、公司连接参数、规则、库存来源及权限、熔深与 MES 配置；只修改已确认的主机部署项。 |
| `runtime/members.json` | 如已生成，保留全部成员、角色、启用状态、密码摘要及版本。已有成员库不得重新初始化或用空库替代。 |
| `runtime/inventory-scope.json` | 保留工艺部备件范围；若配置使用 `inventoryScope` 或 `inventoryScopePath`，一并保留对应内嵌配置或外部文件。缺失不能扩大为全公司库存。 |
| `runtime/inventory.json` | 如存在，完整保留库存操作、幂等请求、盘点及未知结果；不能清空，也不能仅复制完成记录。 |
| `runtime/product-aliases.json` | 保留历史名称/代号映射；原名显示模式仍需要兼容历史代号筛选。 |
| `runtime/penetration/cache.json` | 保留已解析熔深记录及覆盖诊断。 |
| `runtime/penetration/pending.json` | 如存在，保留未完成扫描的进度缓存；它不代表完整扫描已成功。 |
| `runtime/vision/records.json`、`runtime/vision/catalog.json` | 如存在，作为历史采集记录与台账原样保留。当前 MES 不读取、不导入、不混算这些文件，不能用它们的条数验收 MES。 |
| `public/login-help.local.txt` | 仅在继续使用原登录提示时私有转移。该提示会向门户访客显示，不可放管理员密码或公司凭据。 |
| TLS 证书、私钥及其他配置引用的外部文件 | 由维护人员私有转移或在新主机重新签发、配置；保持路径与实际运行账号的权限一致。 |
| 旧 CSV、SQLite、采集 JSON、`vision-relay.local.json` 及采集器私有配置 | 在原机保留或独立归档，供历史追溯和维护；不作为 MES 运行依赖，不放到 `public/`。 |

原本不存在的可选文件不需要创建空文件。迁移前后的业务记录、文件哈希、现场截图和对账报告只保存在受控内部位置，不提交公开仓库；Git 忽略规则不能代替交付前的内容核对。

`runtime/source-credentials.dpapi.json` 只作为旧机私有备份保留，不当作新机可用凭据。`runtime/portable-launcher/` 的控制文件、状态、日志以及库存锁、未完成临时文件不是业务备份恢复入口。确认旧实例已完全退出后，目标运行副本不沿用这些进程状态；保留原始备份供异常核查，不删除正在运行源程序的锁文件。

## 账号配置与启动切换

1. 确认版本、完整程序文件和 Node 运行时，恢复上表私有文件到新电脑本地可写目录。迁移已有账号时不要运行 `npm run setup`；该命令仅用于新部署初始化，重新设置初始管理员可能与已有成员库不匹配。
2. 核对新主机的 `config.local.json`。公司 API、网页登录地址和登录参数由获授权维护人员提供；`vision.mes.defaultLineId` 只能填写当前目录中的线体 ID，`maxPages` 的口径见 MES 文档。不要为视觉检具配置共享采集文件路径。
3. 在实际运行门户的身份和启动环境中核对凭据来源。若使用环境变量，`PORTAL_SOURCE_USERNAME` 与 `PORTAL_SOURCE_PASSWORD` 必须同时有效；任意一项存在就选择环境变量，缺一项或为空会报错，不回退 DPAPI。环境变量管理期间，“数据源设置”不能覆盖或清除它们；由维护人员修改后重启。不要把明文写入 `.cmd`、公开配置、命令记录或交接文档。
4. 双击 `启动门户.cmd` 启动后台门户并打开浏览器；重复启动会复用同一目录的实例。已有账号摘要不绑定 Windows，原账号密码仍可用于登录；旧门户会话在内存中，迁移后必须重新登录。公司账号与门户成员账号是两套配置，门户登录成功不等于 MES 可用。
5. 若使用 Windows 本机保存，在新电脑或新 Windows 用户下以管理员门户账号登录，通过“数据源设置”重新验证并保存公司账号。加密实现使用 DPAPI `CurrentUser`，不能假设复制密文便可迁移登录状态。非 Windows 使用受控环境变量，程序不回退明文保存。
6. 按下一节只读验收通过后切换使用入口。旧机保持停写和备份，不同时提供库存写入入口。若新机已产生业务操作，不得直接以旧快照覆盖新库或回滚到旧机继续操作，先核对后续业务与未知结果。

停止后台门户使用同目录的 `停止门户.cmd`；关闭浏览器或退出账号不会停止服务。`npm start` 和 `startup-diagnostics.cmd` 都实际启动门户，可能恢复公司自动连接和熔深共享表扫描，**不是离线检查命令**；前台启动需在原窗口按 `Ctrl+C` 停止。启动器不创建 Windows 服务或开机任务，重启电脑后需再次启动。

需要离线验证时，仅在不含私有配置/凭据的隔离副本运行 `npm test`，并在测试子进程环境中清除继承的 `PORTAL_*` 业务环境变量，尤其 `PORTAL_PENETRATION_DIRECTORY`；部分服务测试没有替换熔深服务，继承真实目录会触发实际共享表扫描。无需修改生产进程的环境配置。不要使用真实配置或凭据启动服务；“启动诊断”不能替代生产连接授权。

## 只读连接与数据完整性验收

前提：以下步骤由公司授权维护人员在目标主机执行，仅登录和读取已开放的 MES 接口；本次仓库修正不执行这些现场操作，不触发入库、出库、盘点、复核或调账。所有核对条件与结果留在内部。

1. **先核对本地保留项。** 在首次启动前确认私有文件副本一致。启动后核对成员与角色、备件范围及原有操作/未知结果是否保留；只查看记录，不提交交易。核对熔深年度、已有覆盖诊断和产品筛选。读取可能更新本地缓存和代号映射，所以不要用启动后的缓存哈希变化判定迁移丢失。
2. **再核对公司账号。** 数据源显示已连接，仅证明公司会话已建立；不能替代该账号的尺寸目录、报表与详情权限验收。在视觉检具实际读取目录，确认预期线体可见且符合门户的发现/排除规则。出现目录项或空结果都不足以证明历史数据完整。
3. **按固定范围对账。** 选择已知有记录的一条检测线体及已经结束的短时间段，按时间模式查询。在同一账号可见范围内，用 MES 报表核对记录 ID、SN、检测时间、物料、设备、原始 OK/NG、总次数及 OK/NG 次数；同 SN 复测按不同记录 ID 分别保留。固定相同线体、北京时间边界和筛选条件，不把页面当前分页条数当作总数。
4. **单独验收数量模式和详情。** 按最近 N 次查询，核对实际最早/最晚检测时间与 N 次筛选结果；它不应用日期框，也不是“今天 N 次”。结果少于 N 时，须同时确认 `coverage.sourceExhausted` 和完整性检查通过。再从刚读到的记录打开至少一条详情，核对测点、上下限及原始判定；如有 OK/NG、复测和跨日样本，应分别抽查。历史 NG 查询不能替代当前报表或作为分母。
5. **检查完整性而非只看 HTTP 200。** 查看页面覆盖说明、完整性提示和实际查询范围。重复 ID、总数变化、排序异常、未读完、超时、复核失败等出现时视为部分结果；缩短范围后重新对账，仍不一致时停止验收并交维护人员核查。当前最多读取 150 页、每页 200 条，一次读取上限 45 秒；数量模式最多选择 20000 次，均不保证公司全部历史可读。工序混合、未知判定或选择单件/单一结论时，能读取记录也不意味着可以计算整线合格率。
6. **按需要核对报告。** 完整且非空的同一已应用范围才能生成检测报告；核对报告条件和统计与列表一致。测点分析另要求不超过 1000 次且全部详情读取成功，不能以少量详情通过代表全部测点已取得。导出仅作内部证据。
7. **核对连接恢复。** 在维护窗口重启服务、重新登录并重查相同已结束区间，确认新主机凭据可用和数据口径一致；不要复用旧列表的详情 ID 或分析快照。新增线体须分别验收，不能由一条线推定全部线体已接通。

局限性：门户的完整性标记说明本轮可见 MES 记录经过读取检查，不证明现场全部检测已经上传。MES 未提供分页快照；即使冻结结束时间、核对总数/排序并复核第一页，仍可能有其他页旧记录在读取期间被修改。页面刷新时间是取数时间，不能视为检具上传时间；没有新记录不等于检具断线。MES 未提供已核实的全检标识，不能承诺与旧 CSV“排除全检”完全同口径。详细口径见 [公司尺寸接口接入](公司尺寸接口接入.md) 和 [公司测点统计口径](公司测点统计口径.md)。

## 历史采集与共享盘维护（不用于当前 MES 部署）

适用前提：维护人员明确维护旧采集产物或已单独确认的历史部署版本。保留 `collector/`、`lib/vision*.cjs` 中的旧适配器、中转程序及历史文件，不代表当前 `server.cjs` 还支持该链路；不能靠环境变量恢复已停用的 HTTP 入口。若将来需要恢复历史门户读取，应另行评审版本与权限，而不是把旧文件混入 MES 结果。

```text
历史现场 CSV → 历史采集程序 → 采集 JSON
                                  ↓ 只读来源
                          中转程序 → 共享目录 JSON
                                  ↓
                     仅供已确认的历史消费方读取
```

历史维护可保留以下操作说明：

- 将 `vision-relay.example.json` 复制为被 Git 忽略的 `vision-relay.local.json`，由维护人员私下填写 `sourceFile`、`destinationFile`。`node vision-relay.cjs --once` 校验并转发一次，`--watch` 持续转发，`--stop` 请求停止同目录中转实例。中转会写目标共享文件，应只在明确维护历史链路时使用。
- 历史文件连接检查用 `npm run vision:check:legacy`，或 `node check-vision-connection.cjs --legacy`。它只检查采集文件可读性、格式与扫描时间，不导入记录。`vision.dataFile`、优先级更高的 `PORTAL_VISION_DATA_FILE` 只对这类旧适配器生效；检查须使用历史消费方的 Windows 身份和配置环境。返回 `mesVerified: false` 不因检查成功而改变。
- 使用完整 UNC 路径并核对实际运行账号的权限；不把共享账号密码写进路径配置。中转保留设备标识、原记录及 `last_scan.scanned_at_utc`；复制成功时间不能改写为现场扫描时间。完整校验后以临时文件替换正式文件，失败保留上一份，不用空文件覆盖。
- `runtime/vision/records.json` 是旧门户累计历史，不是采集 JSON，不能直接作为中转源。共享盘只传采集输出，不发布成员、配置、凭据或整个 `runtime`。
- 旧采集输出曾采用今天、昨天的窗口；中断跨出窗口的记录不会靠最新快照自动补回。保留原 CSV、SQLite、历史累计记录与原扫描时间供受控追溯，不能清空后仅接最新 JSON。旧采集格式/存储仍受 20000 条及 128 MiB 等保护限制，中转不提高容量、不证明历史完整。

完整历史适配与格式说明见 [视觉检具接入](视觉检具接入.md) 和 [其他检具接入流程](其他检具接入流程.md)。这里的历史扫描时间、共享读取成功与历史数量都不能用于验收当前 MES。

## 熔深共享表及手机访问

视觉检具切换 MES 不等于其他模块都不再使用共享目录。熔深仍使用单独配置的共享表来源；`PORTAL_PENETRATION_DIRECTORY` 优先于 `penetration.directory`。保留年度、原路径写法和缓存；缓存按目录字符串与年份绑定，UNC 换成盘符或另一种等价路径也会导致旧缓存不复用，需重新扫描并核对覆盖。详见 [熔深接入与名称显示](熔深接入与保密显示.md)。库存来源身份也受 API 地址、租户、协议和仓库标识影响，迁移不应随意改动或合并这些项。

迁移不自动开放手机访问。默认门户仅监听回环地址；局域网访问需管理员配置受信任 HTTPS、`tls.certFile` / `tls.keyFile`、准确的 `publicOrigins` 和限定范围的网络访问。反向代理场景后端仍需 TLS，并保留外部 `Host` 与原始 `Origin`，不能仅依靠 `X-Forwarded-Proto`。详见 [手机访问与部署](手机访问与部署.md)；电脑浏览器通过不能替代真实手机的登录、相机、文件选择和下载验收。
