# 其他检具接入流程

适用对象：现场负责人、门户管理员、维护人员与生产网络 IT。更新日期：2026-10-15。

**可以继续使用“检具采集 → 只读共享 → 门户显示”的方式，但必须以最终部署服务器能够读取共享为前提。** 当前先提供线体、检具选择和“登记检具”管理入口；登记保存的是待配置台账，不会自动创建采集程序、连接共享或生成检测数据。

## 先确认网页将部署在哪里

| 部署位置 | 可采用的接入方式 | 需要满足的条件 |
| --- | --- | --- |
| 厂内 Windows 服务器或固定电脑 | 检具持续生成采集结果，门户服务端使用 UNC 路径读取授权的只读共享 | 最终服务器与检具网络可达；实际门户服务账号有共享及文件读取权限。不要依赖个人会话中的映射盘符。 |
| 厂内 Linux 服务器或容器 | 由 IT 将 SMB 结果共享受控挂载为只读目录，门户使用挂载后的绝对文件路径 | 挂载、认证、进程或容器的读取权限及重启恢复均需验收。不能把 Windows UNC 字符串直接粘成 Linux 文件路径。 |

本机和公司内网部署统一保留 SMB 文件接入。**共享传输与网页访问是两层：服务器读采集文件，浏览器和手机只访问门户 HTTPS。** 浏览器无需连接 SMB 或保存共享密码。具体服务器尚需落地验收；开发电脑能读取，不代表新服务器和实际服务账号可读取。当前方案不提供 HTTPS 主动上传，也不更改现场 EXE。

Windows 服务应使用 UNC 和正确服务身份，依据见 [Microsoft：Services and Redirected Drives](https://learn.microsoft.com/en-us/windows/win32/services/services-and-redirected-drives)；Linux 挂载选项见 [Ubuntu：mount.cifs](https://manpages.ubuntu.com/manpages/noble/man8/mount.cifs.8.html)。共享认证与挂载由 IT 管理，不把密码写入门户配置路径或公开资料。

## 统一文件源与后台同步

| 门户端设置 | 规则 |
| --- | --- |
| `PORTAL_VISION_DATA_FILE` | 设置后优先采用的文件路径环境变量；空白值报配置错误，不回退旧路径。只填路径，不填凭据。 |
| `vision.dataFile` | 继续兼容原私有配置；没有环境变量覆盖时使用它，无覆盖时默认 `runtime/vision-input.json`。 |
| `vision.pollIntervalSeconds` | 后台同步间隔默认 30 秒，允许 5–3600 秒。 |
| `vision.readTimeoutMs` | 文件读取超时默认 10000 毫秒，允许 1000–60000 毫秒。 |

门户服务运行期间，即使无人打开页面也会后台同步，页面查询读取缓存。同一服务实例的同步不重叠；共享读取超时、损坏或校验失败时保留旧记录并显示异常。这不改变现场 v2 的采集周期和今天、昨天的快照范围。扫描过旧的默认两小时宽限另由 `vision.maxScanAgeSeconds` 管理，不是同步间隔或读取超时。

读取期限不能取消底层 SMB 调用：超时后保留同一在途读取防止堆积，底层返回后后续轮次才能继续；若系统连接一直不返回，需恢复挂载或 SMB 连接，必要时重启门户后核对，不能保证任何断网都自动恢复。

在最终服务器的门户目录，以实际门户服务账号和相同配置环境运行 `npm run vision:check`，只读核对连接与输入格式；自检不写真实业务数据，不打印检测记录、源路径或凭据。一次成功不代表历史完整或重启后一定可读。

## 如果以后放到厂内服务器，需要重新配置什么？

**换一台服务器，需要部署和验收服务器这一侧；在共享读取方式不变、检具输出和共享路径不变的前提下，检具端采集程序通常不用改。** 由服务器主动读取检具共享，服务器地址变化并不要求检具向新地址发送数据。同事届时通过新的网页地址访问。

维护人员与 IT 按以下清单迁移，当前尚未实施这些部署操作：

- [ ] 在新服务器部署门户程序与运行环境，确认实际使用的服务账号。
- [ ] 安排维护时段停止原门户写入并备份；若目标服务器已有业务数据，也先停止相关服务并备份。迁移原 `runtime` 历史记录、检具台账及其他业务数据，核对数量、登记和配置，避免用空目录或默认文件覆盖已有数据。
- [ ] 保留原检具设备编号及来源归属，现有 `vision-01` 继续使用，迁移不新建一个编号替代它。
- [ ] 检具共享未变时保留原来源；Windows 使用 UNC，Linux 或容器由 IT 先只读挂载再配置绝对路径。核对 `PORTAL_VISION_DATA_FILE` 是否覆盖了预期的 `vision.dataFile`。
- [ ] 由 IT 在新服务器本机配置必要的共享凭据。凭据不会随代码从旧电脑自动迁移，密码由授权人员自己填写，不写进迁移文档或聊天。
- [ ] 在实际服务身份及相同配置环境下运行 `npm run vision:check`，重新验证网络、共享、挂载及文件权限。
- [ ] 配置并验证门户开机启动，以及重启后的共享认证和读取；同时确认检具原有持续采集仍正常。
- [ ] 不打开查看页面时验证后台仍能同步；在受控环境验收读取超时、旧记录可查询、错误提示、恢复读取和同步不重叠。
- [ ] 按需要访问的人员和范围配置网页监听地址、限定的防火墙规则及 HTTPS，在同事电脑或手机上验收；本机打开成功不能替代访问端验收。
- [ ] 保留现场 SQLite 与原 CSV；核对迁移停机和断网是否造成超出两天快照的缺口，必要时安排受控补接，不承诺当前会自动补齐历史。
- [ ] 比对迁移前后的历史记录、设备归属、最新检测和页面状态，通过后再切换用户访问地址，并保留可恢复的原备份。

**如果只是让同事访问当前这台电脑，不需要因此重新配置检具采集。** 维护人员需要单独处理网页的网络监听、访问范围、防火墙和 HTTPS，并完成异机访问验收。当前服务仅监听本机回环地址，只能视为本机可用，不能据此宣称已在局域网开放。

## 分工与接入步骤

### 1. 现场负责人：收齐设备资料和实际样例

- 列出线体名称、检具名称、型号和台数，一台检具填一张信息表。
- 确认检测结果由哪个软件保存、普通 `backup` 在哪里，以及实际日期目录和文件名结构。不要只提供相机图片或点云文件来代替检测结果。
- 提供正常检测 CSV 和实际 NG 样例；如有缺测、复检等异常情况，再提供对应真实样例。样例需保留字段结构，可按公司要求脱敏。
- 若暂无某类样例，明确写“待补样”，不编造结果，也不把未验证的情况标为通过。
- 记录检具网络地址、网络所属区域、现场联系人和生产网络 IT 联系人。地址仅交给有权限的维护人员，不写入公开页面。

**本步交付：** 完整资料表、可读取的实际样例、仍待确认的事项。

### 2. 门户管理员：登记检具，确定唯一编号

在“视觉检具”中选择“登记检具”，填写线体名、检具名、唯一设备编号、共享或上传方式、路径、型号、测点数及备注。路径未确定时写“待维护确认”；选择上传仅记录计划。

- `vision-01` 保留给现有前副车架检具，新设备分配新的唯一编号。
- 一个设备编号只能对应一台检具；同一台设备后续继续使用原编号。搬迁、改 IP 或更新程序时不要随意改编号。
- 不同检具可能出现相同 SN，不能以“SN 不会重复”代替设备编号管理。
- 保存后仍是待配置台账。检具选择项或卡片出现，不表示已经连接，也不会自动获得检测记录。
- 备注、路径和任何页面字段中都不要填写密码。

**本步交付：** 一条待配置登记记录和已确认的设备编号。

### 3. 维护人员：验证格式，生成该设备专用采集配置

维护人员使用实际样例核对型号、测点名称与数量、关键点标志、SN、时间、整体与逐项判定、数值和缺测写法。单位、时间含义或判定规则不清楚时，由现场或设备供应商确认，不自行猜测。

确认后生成绑定该设备编号、源目录与输出目录的采集配置和程序包。现有包固定 `vision-01`，不能直接分发给所有检具；其他型号也不能直接套用现有 61 项规则。

同时确认门户接入方式：当前 `dataFile` 只有一个自动读取来源。要保留现有检具并新增另一台，维护人员必须先实现并验证多来源读取或汇集方案，不能直接用新路径覆盖现有路径当作“新增成功”。

**本步交付：** 已验证的样例结果、设备专用采集包、明确的服务端接入方案。未完成适配时保持待配置。

### 4. 现场人员与 IT：运行采集，开放限定的读取权限

按设备专用说明启动采集程序，先采集一次并核对，再开启持续采集。使用菜单式工具时，选择“持续采集”并保持窗口运行；关掉窗口后不应假定它仍在后台工作。

输出放在源 `backup` 之外的独立目录，由该程序生成 `data/vision.json`。只共享采集结果文件夹，不共享整个硬盘。现有 v2 默认采集和输出今天、昨天的数据；需要补历史时，由维护人员另行安排范围与容量，不能把近期数据当作完整历史。

IT 为最终门户服务身份安排读取权限，必要时使用专用的非管理员读取账号。共享权限、文件权限和 Linux 挂载权限均需核对；凭据由授权人员在操作系统的受控认证配置中管理，不发到聊天，不写进说明、页面或脚本。保留检具生产程序正常写入所需的权限。

跨网段访问由 IT 核对路由和指定共享访问策略。连接同一 Wi-Fi 不能代替这些检查；具体网络配置应按现场环境处理。

**本步交付：** 持续更新的采集输出、经过授权的读取方式和明确的运行负责人。

### 5. 维护人员与 IT：在最终部署服务器验证

- 在将来实际运行门户的服务器上验证读取，不只在个人电脑或资源管理器中验证。
- 使用门户服务实际运行的身份和相同配置环境执行 `npm run vision:check`；个人登录账号能读，不代表服务账号能读。
- 核对文件更新、最后扫描时间及错误状态，而不只是“共享文件夹能打开”。
- Windows 配置 UNC；Linux 或容器先完成只读 SMB 挂载，再配置挂载后的绝对路径。文件路径只存在服务端，浏览器和手机通过门户 HTTPS 查看。
- 检查环境变量是否覆盖私有配置，验证无人查看时后台更新、超时错误提示和恢复情况。不要把一次自检通过等同于完整链路验收。

Windows 占位示意：`\\<检具主机名或地址>\<采集结果共享名>\vision.json`；Linux 挂载后示意：`/mnt/vision-01/vision.json`。实际路径由维护人员按实机填写，示意路径不能直接照抄，也不能携带凭据。

**本步交付：** 在最终服务器、最终服务账号下通过的文件读取与后台同步记录。

### 6. 现场负责人和维护人员：单台验收

先选一台新检具，逐项确认：

- [ ] 与检具原软件比对同一 SN、检测时间、整体 OK/NG、测点名称和数量、关键数值。
- [ ] 逐项 NG 与整体判定分别保留；不将测点合格率误当成零件合格率。
- [ ] 相同文件重复读取不增加检测次数；同 SN 不同时间的复检仍可区分。
- [ ] 切换线体或检具后只出现对应来源；用可追溯样例确认多台检具不会串数据。
- [ ] 检具新增一次实际检测后，采集文件、扫描时间和网页记录按链路更新。
- [ ] 无人打开页面时后台仍接收新记录；在受控环境验证读取超时不阻塞页面查询、旧记录仍可看、错误状态准确和同步不重叠。
- [ ] 采集暂停或网络不可用时，页面按实际情况显示等待或异常；旧记录不被当成最新结果。
- [ ] 在安排好的维护时段验证检具电脑和门户服务器重启后的采集启动、网络、认证与服务恢复。
- [ ] 对暂无的 NG、缺测或其他异常样例明确记录“待验证”，不以模拟数据替代现场验收。
- [ ] 确认历史保留、容量处理和故障联系人，核对两天快照窗口以外的缺口及受控补接安排。

**本步交付：** 有日期、负责人和未完成项的单台验收记录。重启恢复尚未验证时，不宣称可无人值守长期运行。

### 7. 门户管理员：分批启用其他检具

单台链路通过验收、且多来源能力已经完成后，再按线体分批启用。每台都使用自己的编号、配置包和核对记录。每新增一批都确认来源归属、最近更新时间和整体容量；未完成适配的登记继续保持待配置。

## 前提条件与局限性

本流程以获得授权、能提供实际检测结果样例、现场及维护人员可以配合为前提。现有接入证明的是已经适配的前副车架链路，不代表任何品牌、型号或台数都可直接接通。设备登记不突破当前单来源、格式及容量限制；部署形式确定后，还需在最终环境重新验收。指南提供操作分工，不代表已为其他设备实现多来源接口、上传接口、开机自动启动或完成现场接通。

门户停机或共享断开超出 v2 今天、昨天的输出窗口时，可能漏接已退出快照的检测；短于两天也需按跨日边界核对。后台同步不能回补服务停机期间的全部历史。迁移必须带上原 `runtime` 历史记录和台账，并保留现场 `data/vision.sqlite` 与原 CSV。补接需维护人员结合 20,000 条和 128 MB 上限安排，当前不自动从 SQLite 补齐，也不自动归档扩容。
