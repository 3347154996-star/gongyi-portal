# 手机访问与部署

当前页面已做响应式适配，但手机访问还需要部署入口。现有服务默认只在电脑的 `127.0.0.1:4173` 监听，手机不能通过这个地址访问电脑；手机中的 `localhost` 也指手机自身。公开 GitHub 仓库提供源码，不提供已运行的业务服务。

## 前提条件

- 部署主机持续运行 Node.js 服务，并能访问所需业务系统或采集文件；管理员已配置门户账号、数据源与模块权限。
- 手机通过同一可达网络或获准的 VPN 访问部署入口；同一 Wi-Fi 仍可能存在终端隔离，需要管理员核对路由、DNS 和主机防火墙。防火墙只放行计划使用的 HTTPS 入口及授权网段。
- 入口使用与域名匹配、手机信任的 HTTPS 证书。由管理员确定实际域名；本文不包含公司地址或证书私钥。

## 建议部署方式

建议由可信 HTTPS 反向代理提供入口，门户后端仍绑定回环地址。**按当前代码，代理到后端也必须使用 HTTPS**：服务端根据自身 TLS 配置与请求 `Host` 校验来源，目前不会读取 `X-Forwarded-Proto`。仅在代理终止 HTTPS、再转发到现有 HTTP 服务的配置不能直接套用，可能出现 403 或无法登录。

管理员实施时需完成：

1. 保持 `listenHost` 为 `127.0.0.1`；在本机 `config.local.json` 中配置 `tls.certFile`、`tls.keyFile`，使回环服务启用 HTTPS。证书文件路径相对项目目录解析，私钥与本机配置不得提交 GitHub。
2. 用 `publicOrigins` 登记手机实际使用的完整 HTTPS 来源，例如示意值 `https://portal.example.com`；包含非默认端口时须保留端口，不含子路径、查询参数或账号信息。
3. 代理转发到启用 TLS 的回环服务，保留外部 `Host` 和浏览器原始 `Origin`；校验后端证书的名称与信任链。不要改写 `Origin` 来绕过来源检查。将门户部署在域名根路径，现有接口使用 `/local/`、`/tools/` 等绝对路径。
4. 核对登录、会话 Cookie、退出及各模块读取后，再向手机用户提供入口地址。仅出现登录页不能证明业务连接与权限已经接通。

本次只补部署说明，未改监听地址、证书、配置或防火墙，也未开放网络入口。服务端约束见 [server.cjs](../server.cjs)。

## 手机功能与替代操作

实时相机扫码需要浏览器安全上下文和用户授予相机权限；权限被拒、系统限制或相机被占用时仍可能失败。当前备件界面提供“拍摄／选择照片识码”和手动输入编号作为替代，实际拍摄入口由手机浏览器决定。依据：[MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)。

焊接工具提供文件夹选择及多文件选择。目录选择取决于浏览器和系统文件选择器，不承诺所有手机可用；不支持时可选择多个 `.mod / .sys / .txt` 文件。多文件选择通常不保留目录层级，应按单一任务分批导入并核对结果；需要区分多个 `TASK` 的备份优先用电脑按文件夹导入。参见 [MDN webkitdirectory](https://developer.mozilla.org/en-US/docs/Web/API/HTMLInputElement/webkitdirectory) 和 [文件输入的 multiple 属性](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input/file#multiple)。

检具对比可分别选择两份 `.xlsx / .xlsm` 报告。工具文件在当前页面本地解析，手机仍受内存与文件体积影响；关闭页面前先保存结果。导出文件的保存、预览、分享位置需要在目标手机上核对。

## 验证范围与局限性

截至 2026-10-15，已进行 **390 × 844 浏览器模拟视口**验证，尚未完成真实手机验收，也未验证上述网络部署。模拟视口不能代替触摸、软键盘、相机、文件选择器及系统下载行为验证。

部署后应在计划使用的 Android／iPhone 和实际浏览器上核对：登录与退出、各模块导航与横向表格、筛选与分页、相机授权及拒绝后的替代入口、两工具导入与导出、切到后台再回来以及网络中断后的恢复。库存写入权限与生产过账需单独现场验收，不能由手机页面能打开推定通过。
